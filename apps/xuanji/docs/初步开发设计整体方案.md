# 璇玑数字观象台初步开发设计整体方案

本方案面向没有开发经验的项目负责人，目标是把《06-璇玑-创意文档.md》中的创意，转成可以开始执行、可以验收、可以暂停或继续的产品计划。创意文档提供的是愿景、假设和初始要求；它不是已经确认的技术规格，也不是必须一次性实现的功能清单。本方案结合当前无依赖原生 JavaScript、SVG 原型的真实状态，对内容做取舍，并把尚未核验的历法和文化解释单独标注。

> **形态修订（2026-10-04）**：负责人已确认璇玑的主要产品形式是 Windows 优先的桌面客户端。现有网页静态版本保留为开发预览和备用体验，不再作为主要交付形态。桌面客户端的边界、Electron/Tauri 路线、窗口验收和安装包门槛见 [桌面客户端形态修订](desktop-client-plan.md)；本段修订优先于本方案中仅针对网站、浏览器或手机发布的旧表述。

> **价值重设计修订（2026-10-05）**：原型复测表明“生成一张盘并分享”只能形成一次性新鲜感，不能证明桌面客户端有持续使用价值。因此新的 MVP 主线统一为“今日观象 → 选择一个行动镜头 → 记录一件真实发生的事 → 观象日志 → 七日复盘”。总盘、五行、命纹和星官保留为“我的底色”资料与视觉锚点，不再占据每次打开后的主任务。完整字段、页面、导出边界和验收指标见 [观象记录价值闭环设计](value-loop-local-journal.md)。

当前原型可以验证“输入生日 → 生成总盘 → 查看五行和命纹 → 分享”的体验；它仍使用近似节气边界和固定演示数据，不能被宣传为正式排盘、预测或科学测量工具。二十八宿和生日节气的精确计算，必须在正式发布前用有来源的历法资料复核。香港天文台将二十四节气定义为太阳黄经每 15° 的时刻，并说明具体时刻受年份和时区影响：[二十四节气](https://www.hko.gov.hk/en/gts/time/24solarterms.htm)、[二十四节气的日期和时间](https://www.hko.gov.hk/en/gts/astronomy/Solar_Term.htm)。

## 第一部分：项目理解与一句话定位

### 1. 你认为这个项目真正要解决什么问题

项目真正要解决的是“看完一张盘以后，用户没有理由再次打开”的问题。璇玑把传统时间、五行和星象符号转译成一种有来源的观察语言，再把用户每天写下的事实、感受和小行动沉淀成可回看的本地记录。盘面负责提供文化视角和视觉锚点，今日记录与七日复盘负责产生持续使用价值；系统只整理用户写下的内容，不替用户预测或作决定。

### 2. 它服务什么人、什么场景

- **主要用户**：对传统文化、视觉设计和自我观察感兴趣的 18 岁以上 Windows 用户，尤其是需要在工作、学习或创作中定期整理状态的人；不要求会看八字或懂天文。
- **使用场景**：每天打开桌面客户端，用 3 分钟选择一个行动镜头、记录一件具体的事，周末回看近 7 日的精力、专注和完成情况；盘面和分享卡作为个人底色与附加成果。网页版本只用于开发预览和备用体验。
- **不优先服务的人**：需要专业命理排盘、医学或心理诊断、婚姻/投资决策的人。产品必须明确把这些用途排除。

### 3. 用一句话说明产品是什么

璇玑是一款 Windows 本地观象工作台：把出生日期转成有来源说明的个人底色，再帮助用户记录每天的一件事并回看自己的节奏。

### 4. 用一句话说明它不是什么

它不是预测人生、替用户作决定、提供心理诊断或可以代替专业历法软件的工具。

### 5. 用户第一次使用后应该获得什么感受或结果

用户第一次使用后应在 90 秒内看到“今日观象”入口，并在 3 分钟内保存一条包含一件事、一个行动镜头和当下状态的记录。用户离开时知道记录只保存在本机，也知道下次可以从日志和七日复盘继续，而不是只记住一张分享图。

### 6. 创意文档中最有价值的三个点

1. **总盘是内容和导航的同一个对象**：盘面、入口和结果合在一起，能把复杂内容隐藏在逐层下钻里，避免首页像后台管理系统。
2. **命纹和一人一色有传播潜力**：同一组输入稳定生成相同图形和主题色，既方便保存，也能形成“这是我的结果”的记忆点。
3. **把传统符号当作文化语言而非预言**：若每条结论标注来源、确定性和争议，项目能同时保留审美和可信边界。

### 7. 创意文档中最容易导致项目失控的三个点

1. **一次承诺十二席完整模块**：大运、五格、称骨、合婚、二十五人对照都各有独立数据和争议，若同时开始，核心体验还没有被验证就会进入资料和界面泥潭。
2. **把近似算法当成正式历法**：固定日期表、二十八日循环和缺少时区的日柱只能做原型降级方案；一旦用户把结果当成事实，风险会从技术问题变成信任和合规问题。
3. **五音音效、Canvas 图片、惯性盘面等多感官功能过早加入**：它们增加浏览器兼容、版权、性能和无障碍工作量，可能掩盖“用户是否真的想看自己的盘面”这个首要问题。

## 第二部分：需求拆解

下表中的“实现难度”按一个会使用 AI 工具、但没有独立开发经验的负责人估算：低是数小时到两天，中是几天到两周，高是需要资料专家或专门开发者共同完成。“进入 MVP”指第一版必须稳定交付；标为“演示保留”的功能可以在原型里出现，但不能成为正式发布承诺。

### A. 核心价值功能

| 需求 | 用户价值 | 实现难度 | 依赖内容 | 进入 MVP | 不做的后果 |
|---|---|---|---|---|---|
| 姓名可选、生日必填的输入 | 让用户在一分钟内开始 | 低 | 表单校验、日期范围 | 是 | 没有个人化起点 |
| 三柱近似结果和明确口径 | 把输入变成可读的文化标记 | 中 | 干支映射、近似节气表、来源说明 | 是，必须写“原型近似” | 盘面只有装饰，没有内容 |
| 五行比例和主色 | 给用户一眼可理解的视觉结果 | 低至中 | 天干地支映射、颜色规则 | 是 | 失去“看见个人差异”的核心反馈 |
| 总盘 SVG 视觉和鼠标/触摸拖动 | 形成产品独有的仪式感 | 中 | SVG 绘图、指针事件、移动适配 | 是 | 产品退化成普通表单报告 |
| 命纹稳定生成 | 提供个人记忆点和可重复分享 | 中 | 可复现哈希、SVG 图形 | 是 | 分享结果缺乏辨识度 |
| 详情下钻和返回总盘 | 让用户按兴趣渐进阅读 | 低 | 页面状态、键盘入口 | 是 | 用户不知道怎样继续探索 |
| 分享摘要、SVG 下载和打印路径 | 让用户带走成果 | 中 | Blob 下载、打印样式、浏览器权限 | 是 | 核心体验难以传播和保存 |
| 本地保存、清除记录和隐私说明 | 降低输入顾虑 | 低 | `localStorage`（浏览器本地存储） | 是 | 刷新后丢失结果，用户不信任 |

### B. 必要辅助功能

| 需求 | 用户价值 | 实现难度 | 依赖内容 | 进入 MVP | 不做的后果 |
|---|---|---|---|---|---|
| 示例数据按钮 | 让没有准备生日的用户立即试用 | 低 | 一个已固定且可重复的样例 | 是 | 用户可能停在输入页 |
| 日期上下限和错误提示 | 避免明显无效数据 | 低 | 本地日期计算、可读提示 | 是 | 生成时才报错，挫败感高 |
| 总盘入口的文字列表 | 给不理解 SVG 盘面的用户备用入口 | 低 | 详情按钮 | 是 | 移动端和屏幕阅读器难以操作 |
| 反馈表单并导出 JSON | 收集早期试用意见而不上传资料 | 低 | 本地反馈格式 | 是，限内部试用 | 没有可比较的体验证据 |
| 说明、边界和来源链接 | 让用户知道哪些是事实、演绎和限制 | 低 | 文案审核、来源登记 | 是 | 容易被误解为预测服务 |
| 减少动画设置和键盘操作 | 照顾可访问性和设备差异 | 中 | `prefers-reduced-motion`、焦点顺序 | 是 | 部分用户无法舒适使用 |

| Canvas PNG 导出 | 方便直接发图片 | 中 | Canvas 绘制、字体和下载兼容 | 否 | 可用 SVG 下载和打印替代 |

## 第三部分：核心用户流程

### 当前执行主流程（桌面工作台）

旧原型的“生成—看盘—分享”流程保留为底色查看路径；当前开发以可重复使用的桌面工作台为准：打开客户端 → 默认进入“今日观象” → 看到当天近似节气提示和一个可执行的五行镜头 → 写下一件想推进的事 → 记录精力、专注、心境和备注 → 勾选是否完成 → 保存到本机 → 在“观象日志”按日期回看 → 在“七日复盘”查看记录天数、平均精力/专注、镜头使用和完成事项。复盘只做描述统计，不对命盘与现实事件建立因果关系。

通过现象判断价值：首次打开后 90 秒内能找到记录入口，3 分钟内保存第一条记录；至少连续三天后，用户能说出一个愿意继续打开的理由。若用户只能复述主色或分享卡，说明价值闭环仍未成立，应先改入口和提示，不扩展更多术数模块。

### 主流程

1. **第一次打开**：用户先看到产品用途、资料留在本机的说明和“开始建立我的工作区”。如果已经建立过资料，桌面端直接恢复到“今日观象”。
2. **建立底色**：用户只填写称呼（可选）和公历生日。系统在本机生成三柱近似结果、五行主色和稳定命纹，并明确标注“文化演绎/待核验”。
3. **完成第一条记录**：系统把用户带到“今日观象”，默认给出一个 5 分钟内可执行的观察镜头。用户选择木·启动、火·表达、土·承接、金·收束或水·沉淀之一，写下一件今天想推进的事，再填写精力、专注、心境和备注。
4. **得到即时反馈**：点击保存后，页面显示“已保存在这台电脑”，并在右侧更新最近记录；用户可以继续编辑今天的记录，或打开日志时间线。
5. **核心惊喜**：当用户连续留下几条记录后，“七日复盘”会把记录天数、平均精力/专注、完成事项和镜头使用情况变成一张可读的节奏图。它只总结用户写下的事实，不把命盘强行解释成因果。
6. **回看和带走**：用户可以按日期编辑、删除记录，导出 JSON 备份，再在另一台同样的本地原型中导入；分享卡仍用于带走个人底色，而不是替代日志价值。
7. **再次回来**：下次打开客户端直接进入“今日观象”，页面告诉用户“上次记录了什么”和“今天可以从哪个镜头开始”。用户愿意回来，是因为几分钟记录会逐渐形成自己的时间线，而不是因为系统声称知道未来。

### 备用流程

- **先看说明**：用户从首页进入“说明与隐私”，先读内容边界，再返回输入页。
- **不想填姓名**：只填日期即可，系统使用“观星者”作为展示称呼；不要把空姓名当成身份证明。
- **只想看结果**：点击示例数据，生成固定样例，不要求用户输入真实信息。
- **只想试性格**：在总盘进入“阴阳四维”试验页，调整滑杆后查看文字反馈；页面明确这不是 MBTI 测评或心理诊断。

### 用户中断后的恢复方式

- 用户在输入页离开：不保存未提交表单，重新进入时显示安全的默认日期；若未来要保存草稿，必须先征得同意。
- 用户已生成结果后刷新或关闭页面：从 `localStorage` 恢复最近一次 profile（个人结果对象）；恢复时重新计算基础字段，并保留已校验的四维滑杆值。
- 用户正在分享弹窗中按 Escape 或点击背景：关闭弹窗，并把键盘焦点还给打开分享的按钮。
- 用户点击“重新开始”：明确清除本地观盘记录并回到首页；不删除下载到设备的文件。

### 没有数据、加载失败或设备性能不足时的降级方式

- 没有数据：显示空盘、说明和“开始观盘”，不显示伪造的个人结论。
- 数据文件加载失败：保留首页和输入页，给出“资料暂时不可用，请刷新或使用示例”的提示；不把 HTML 错误页当作 JavaScript 或 CSS 成功返回。
- Service Worker（浏览器离线缓存）未启用：在线页面仍可用，说明页不要声称已离线。
- 低性能设备或用户减少动画：取消持续旋转、惯性效果和长过渡，直接展示最终盘面；SVG 元素数量保持在当前小规模，不加载大图片或音频。
- 不支持剪贴板：显示可手动复制的摘要或使用打印路径；不阻塞分享卡下载。

## 第四部分：MVP设计

### 第一版的明确范围

**当前桌面执行版的范围优先级**：今日观象、观象日志和七日复盘是核心使用功能；输入页是一次性建档入口；我的底色、三柱、五行、命纹、分享和说明页是辅助资料。第一版最多只保存 365 条轻量记录，单条包含日期、五行行动镜头、精力、专注、心境、想推进的一件事、备注和完成状态。记录导出为用户主动触发的 JSON，允许导入和按日期删除；不自动上传、不自动生成命理结论、不做提醒。

MVP（最小可行产品，指用最少功能验证核心价值的第一版）要验证的是“用户是否愿意在桌面端持续记录，并在七天后从自己的记录中看到可用的变化线索”。个人底色负责建立审美记忆和文化入口，日志闭环负责证明实际使用价值。旧网页原型中的“生成—查看—分享”仍可访问，但不能再作为 MVP 唯一完成标准。

#### 第一版包含的页面

1. **首次建立页**：项目用途、空盘、开始建立工作区、说明与隐私入口。
2. **输入页**：可选称呼、公历生日、示例数据、日期校验和本地保存说明。
3. **今日观象页**：当天节令提示、行动镜头选择、精力/专注/心境、想推进的一件事、备注和完成状态。
4. **观象日志页**：按日期编辑或补写、最近记录时间线、导出 JSON、导入备份、单条删除。
5. **七日复盘页**：近 7 日记录数、平均精力/专注、完成事项、五种镜头使用与完成率、最近 7 条记录。
6. **我的底色页**：个人总盘、主色、三柱、命纹、星官/节气/阴阳四维试验入口。
7. **命盘/五行/命纹详情页**：逐层阅读文化资料和来源说明。
8. **分享弹窗**：个人底色预览、复制摘要、下载 SVG、打印/保存图片。
9. **资料与隐私页**：内容边界、本地数据清除、试用反馈和反馈 JSON 下载。

#### 第一版每个页面的内容限制

- 支持一个称呼（最长 20 个字符）和一个公历日期（1900-01-01 至本地今天）。
- 输出三柱（年、月、日）、五行五项分数、一个主色、一个稳定命纹和一张分享摘要。
- 只使用一套玄青夜景视觉、一个盘面布局、一个命纹算法和一个 SVG 分享卡模板。
- 最多准备 1 个示例数据、3 个核心详情入口、5 个五行类别、1 个分享场景；不做内容库、排行榜或每日更新。
- 当前代码中的“星官、阴阳四维、生日节气”三个入口可以保留为 V2 试验开关，页面必须显示“试验”“近似”“不是正式结论”；若用户测试发现它们分散注意力，下一版直接隐藏，不需要重写核心盘面。

#### 第一版输入与输出

- **输入**：称呼可为空；生日必填；不收集账号、手机号、精确出生地点、上传图片或联系人。
- **输出**：三柱近似结果、五行分布、主色、命纹 SVG、个人底色分享摘要，以及用户自己填写的本地观象记录和七日描述统计。
- **存放**：个人底色和日志只在桌面端本机保存；日志和反馈由用户主动导出 JSON 文件，导入时按日期合并。
- **不能输出**：疾病、寿命、婚姻成败、投资、法律、心理诊断或“吉凶确定答案”。

### 最小可运行切片

一个没有开发经验的人可以把它理解为以下闭环：打开 Windows 桌面客户端 → 使用“知微 / 2000-01-01”建立工作区 → 系统进入“今日观象” → 选择“火·表达” → 写下“完成桌面闭环测试”并保存 → 打开“观象日志”看到这一天 → 打开“七日复盘”看到 1 条记录、精力和专注统计 → 关闭客户端后重新打开，记录仍在。只要这个切片能在目标电脑完成，项目才有资格继续投入内容和安装包工作；分享卡和底色详情属于辅助完成，不再替代这个闭环。

### V2 和 V3 的边界

- **V2**：正式核验节气和三柱样本；决定是否保留星官、生日节气和阴阳四维；补充可审查的来源卡；视用户反馈再做 PNG 导出。
- **V3**：只有在用户确实完成核心流程并愿意分享后，才评估生肖/纳音/太岁、五格、二十五人对照、双雷达、音效、大运、合婚、称骨。每个模块单独立项、单独审查，不以“把创意文档全部做完”为成功标准。

## 第五部分：页面与交互设计

### 页面层级和导航

桌面端页面层级为：**首次建立页 → 输入页 → 今日观象工作台**；工作台左侧导航进入“我的底色、观象日志、七日复盘、资料与隐私”，底色内再进入命盘/五行/命纹及 V2 试验详情，分享以弹窗出现。没有 profile 时不显示工作台导航，避免用户先看到一套空的后台菜单。网页预览保留首页 → 输入页 → 底色查看路径，但不改变桌面端主任务。

主按钮只有“开始建立工作区”“生成并进入今日观象”“保存今日记录”“打开七日复盘”；次按钮用于返回、说明、重新建立观盘、导入/导出和删除。撤销机制包括关闭分享弹窗、放弃日期编辑、删除前确认和 JSON 导入前保留本地备份。复杂算法、来源表和试验口径放在“资料与隐私”或详情注脚中，不在默认工作台一次性暴露。

### 各页面规格

#### 1. 今日观象

1. **页面目标**：让用户在 3 分钟内完成一次现实可执行的小记录，并知道它已经保存在本机。
2. **主要内容**：当天日期和近似节令提示、五种行动镜头、精力/专注/心境、想推进的一件事、备注、完成状态、最近三条记录和个人底色摘要。
3. **主要操作**：选择镜头、填写记录、保存、进入日志、打开个人底色。
4. **页面跳转**：保存后留在今日页并更新最近记录；日志进入时间线；底色进入个人盘；顶部分享打开分享弹窗。
5. **空状态**：没有记录时显示“今天是第一条”和一个具体示例，不显示空图表。
6. **加载状态**：本机计算瞬时完成；若读取本地数据失败，表单仍可用并提示稍后重试。
7. **出错状态**：缺少要推进的事情时，在表单下方提示并保留全部输入。
8. **移动端适配**：表单单列、按钮满宽、镜头选择和三个刻度至少 44px 高，最近记录放在表单下方。
9. **电脑端适配**：左侧表单、右侧底色与最近记录，窗口宽度 860px 以上仍保持清晰层级。
10. **隐藏复杂内容**：不显示五行计算公式、命盘争议和未核验星官，只显示一句“行动镜头是产品化选择”。

#### 2. 观象日志

1. **页面目标**：让用户按日期编辑、回看、备份和删除自己的记录。
2. **主要内容**：日期编辑表单、镜头、心境、精力、专注、事实备注、完成状态、最近 12 条时间线。
3. **主要操作**：保存当天、切换日期、导出 JSON、导入 JSON、删除单条记录。
4. **页面跳转**：保存刷新时间线；复盘进入七日统计；删除后保留当前页面并更新条数。
5. **空状态**：说明记录只保存在本机，并提供“去今日观象”入口。
6. **加载状态**：读取本地记录时显示简单占位，不等待远程网络。
7. **出错状态**：导入文件格式不对时显示原因，不覆盖已有记录；删除必须二次确认。
8. **移动端适配**：表单先出现，时间线纵向排列；导入按钮使用系统文件选择器。
9. **电脑端适配**：左侧编辑、右侧时间线；时间线摘要不展开完整长文，点击日期回填编辑表单。
10. **隐藏复杂内容**：不自动给日志生成性格、命运或因果结论，只显示原始记录和描述统计入口。

#### 3. 七日复盘

1. **页面目标**：把至少 1–7 条记录变成用户能读懂的描述统计，帮助判断是否值得继续记录。
2. **主要内容**：近 7 日记录天数、平均精力、平均专注、完成事项、五种镜头使用次数与完成率、最近记录表。
3. **主要操作**：查看统计、编辑/补写记录、返回今日观象。
4. **页面跳转**：点击“编辑或补写”进入日志；点击今日观象开始新记录。
5. **空状态**：少于 3 条时明确显示“先积累三天记录”，不伪造趋势图。
6. **加载状态**：统计由本机记录即时计算；没有网络时不影响页面。
7. **出错状态**：记录字段缺失时按可用字段统计，并提示“部分旧记录字段不完整”。
8. **移动端适配**：统计卡片单列，表格允许横向滚动但不影响页面主滚动。
9. **电脑端适配**：统计卡片横排，镜头条形图和最近记录并排展示。
10. **隐藏复杂内容**：不做预测、因果分析、排名或把完成率解释成命理正确性。

#### 4. 首页

1. **页面目标**：让用户在 5 秒内知道这是文化可视化体验，并开始操作。
2. **主要内容**：标题、空盘、短说明、开始按钮、约 1 分钟提示、说明与隐私入口。
3. **主要操作**：开始观盘；查看说明；品牌按钮回到首页。
4. **跳转**：开始 → 输入页；说明 → 说明与隐私。
5. **空状态**：空环和“落座，报上名来”，不展示虚构个人数据。
6. **加载状态**：首页不依赖远程加载；若模块脚本未加载，显示静态提示并保留文字说明。
7. **出错状态**：按钮不可用时显示“页面脚本未加载，请用本地服务器打开并刷新”。
8. **移动端**：盘面宽度不超过视口，标题和按钮垂直排列，点击区域至少约 44px 高。
9. **电脑端**：左文案右空盘，内容宽度受限，避免超宽空白。
10. **隐藏复杂内容**：不在首页显示历法算法、数据表、五行百分比或全部模块清单。

#### 5. 输入页

1. **页面目标**：用最少字段完成一次安全、可理解的输入。
2. **主要内容**：称呼、出生日期、两条原则说明、示例按钮、错误提示和提交按钮。
3. **主要操作**：输入、使用示例、生成盘、返回首页。
4. **跳转**：提交成功 → 总盘；返回 → 首页。
5. **空状态**：称呼可空；日期空时保留清晰的“请先选择出生日期”。
6. **加载状态**：计算只需本机瞬时完成；若出现等待，按钮改为“正在生成”，防止重复提交。
7. **出错状态**：日期格式、范围或计算异常在表单下方显示，不使用弹窗打断。
8. **移动端**：使用设备原生日期选择器，输入框满宽，键盘弹起时提交按钮仍可见。
9. **电脑端**：左侧说明、右侧表单，输入宽度适中，不把技术口径放在首屏正文中。
10. **隐藏复杂内容**：隐藏性别、时辰、农历切换和算法参数，直到资料和规则可核验。

#### 6. 我的底色页

1. **页面目标**：用一个视觉对象让用户理解结果，并提供渐进式探索入口。
2. **主要内容**：个人盘面、主色标签、三柱摘要、六个入口（核心三项加 V2 试验项）、本地保存提示。
3. **主要操作**：拖拽/触摸旋转、点击盘钉、点击文字入口、生成分享卡、重新开始。
4. **跳转**：任一入口 → 对应详情；分享 → 分享弹窗；重新开始 → 首页。
5. **空状态**：不允许无 profile 进入总盘；若恢复失败则回首页并解释原因。
6. **加载状态**：显示盘面骨架或“正在落座”；生成完成后再启用入口。
7. **出错状态**：结果对象缺字段时显示“本地记录已失效，请重新生成”，并提供清除入口。
8. **移动端**：盘面和入口纵向排列，文字入口作为主要可点击控件，拖动不阻塞页面滚动。
9. **电脑端**：盘面与概览卡并排，盘面可旋转但不让拖拽抢走所有焦点。
10. **隐藏复杂内容**：不同时显示所有计算过程、源表和争议；放入详情页的来源注脚。

#### 7. 命盘详情页

1. **页面目标**：解释三柱是文化标记，并诚实展示时辰缺失。
2. **主要内容**：年柱、月柱、日柱、虚位时柱、近似节气说明。
3. **主要操作**：返回总盘、打开说明页、生成分享卡。
4. **跳转**：返回 → 总盘；顶部分享 → 分享弹窗。
5. **空状态**：缺失时辰显示“虚位以待”，不默认填午时。
6. **加载状态**：用三个占位印章，避免大块空白。
7. **出错状态**：提示无法生成并回输入页，不给出半截干支。
8. **移动端**：三柱卡片可纵向排列，字号保持可读，长注脚可折叠。
9. **电脑端**：三柱横排，来源注脚放在卡片底部。
10. **隐藏复杂内容**：不显示未核验的节气精确时刻和完整排盘公式。

#### 8. 五行详情页

1. **页面目标**：让用户看懂主色和五项比例的关系。
2. **主要内容**：雷达图、五行条形、主色、建设性意象文案、视觉规则注脚。
3. **主要操作**：返回、分享；图表本身只读。
4. **跳转**：返回总盘；分享弹窗。
5. **空状态**：显示“等待一组出生日期”，不显示默认比例。
6. **加载状态**：先显示五条灰色条，再替换为结果。
7. **出错状态**：条形改为文字错误提示，颜色不作为唯一信息。
8. **移动端**：雷达图不小于 220px；条形旁同时显示数字和文字。
9. **电脑端**：雷达与条形并排，保持视觉焦点在主色和分布。
10. **隐藏复杂内容**：隐藏季节旺衰等未确认权重，不给百分比附加科学含义。

#### 9. 命纹详情页

1. **页面目标**：让用户理解命纹是稳定的视觉生成结果。
2. **主要内容**：SVG 命纹、称呼、主色、确定性说明、分享按钮。
3. **主要操作**：生成分享卡、返回总盘。
4. **跳转**：分享 → 分享弹窗；返回 → 总盘。
5. **空状态**：没有 profile 时显示空印章和“先生成一组资料”。
6. **加载状态**：显示圆形边框和点线，图形生成后再显示。
7. **出错状态**：提供重新生成，不用随机替代图形掩盖错误。
8. **移动端**：命纹先展示，文案后置，分享按钮满宽。
9. **电脑端**：命纹与解释并排，SVG 保持清晰边缘。
10. **隐藏复杂内容**：不展示哈希位运算或“命定”算法字眼，避免宿命误读。

#### 10. 星官 V2 试验页

1. **页面目标**：验证用户是否愿意探索星官意象，不把演示结果包装成正式定位。
2. **主要内容**：四象星图、本命宿名称、动物和项目自写意象；标题标注“V2 试验”。
3. **主要操作**：返回总盘、打开说明页和生成分享卡；星图当前只读。
4. **跳转**：返回 → 总盘；顶部分享 → 分享弹窗。
5. **空状态**：没有 profile 时不显示本命宿，提示先生成日期。
6. **加载状态**：显示简化星图占位，数据载入后点亮一个宿位。
7. **出错状态**：对应表缺失时显示“星官资料待核验”，不随机替换名称。
8. **移动端**：星图缩放到视口内，名称和口径说明在图下方。
9. **电脑端**：星图与说明并排，避免把星点做成密集专业星表。
10. **隐藏复杂内容**：隐藏农历/公历争议和完整对应表，放入来源说明。

#### 11. 阴阳四维 V2 试验页

1. **页面目标**：验证用户是否愿意主动调节四组自我描述。
2. **主要内容**：动静、形神、理情、行化四条滑杆、百分比和中和度文字。
3. **主要操作**：键盘或触摸调整滑杆、返回总盘、查看说明。
4. **跳转**：返回 → 总盘；不生成独立心理报告。
5. **空状态**：默认四条均为 50%，并说明这是中性起点，不是测评结果。
6. **加载状态**：滑杆先显示默认值，结果文字随后同步更新。
7. **出错状态**：异常值恢复到 50%，提示“已恢复默认值”。
8. **移动端**：滑杆轨道满宽、数值紧邻控件，避免小点击目标。
9. **电脑端**：四条滑杆垂直排列，左右标签清晰对齐。
10. **隐藏复杂内容**：不显示 MBTI 判定、心理诊断或性格因果结论。

#### 12. 生日节气 V2 试验页

1. **页面目标**：验证节令意象是否增强个人观盘，而不是提供精确天文时刻。
2. **主要内容**：节气名称、24 段序号、项目自写意象和固定近似日期表说明。
3. **主要操作**：返回总盘、打开说明页和分享。
4. **跳转**：返回 → 总盘；分享 → 分享弹窗。
5. **空状态**：没有日期时显示“等待一组出生日期”。
6. **加载状态**：先显示节令圆环，再填入名称。
7. **出错状态**：日期表缺失时显示“节气资料待核验”，不猜测名称。
8. **移动端**：圆环不超过视口，名称和序号可读。
9. **电脑端**：圆环与意象文案并排，口径说明保持可见。
10. **隐藏复杂内容**：隐藏太阳黄经精确公式和未经核验的时刻表。

若任一 V2 页面在试用中被多数用户误解为正式天文或心理结论，下一次构建默认隐藏入口，保留数据模块等待核验。

#### 13. 分享弹窗

1. **页面目标**：在不离开总盘的情况下完成查看和带走。
2. **主要内容**：分享卡预览、复制摘要、下载 SVG、打印/保存图片、文化体验注脚。
3. **主要操作**：复制、下载、打印、关闭。
4. **页面跳转**：关闭后回原页面和原焦点。
5. **空状态**：没有 profile 时不打开弹窗。
6. **加载状态**：复制操作按钮显示“正在复制”，下载按钮避免重复点击。
7. **出错状态**：剪贴板失败时显示手动复制提示；下载失败时仍可打印。
8. **移动端**：弹窗可滚动，关闭按钮固定可见，分享操作按钮纵向排列。
9. **电脑端**：预览和操作并排，背景遮罩保持足够对比度。
10. **隐藏复杂内容**：隐藏 Blob、SVG 代码和浏览器权限解释。

### 首次使用、无障碍和动效

- 首次使用只用一段短提示解释“这是文化体验、资料留在本机、可以从示例开始”，不做多屏强制教程。
- 所有 SVG 入口同时提供可聚焦文字按钮；键盘 Enter 和空格可打开，焦点顺序与视觉顺序一致。
- 正文最小字号建议 15–16px，正文与背景对比度目标达到 WCAG AA；颜色之外用文字、数字、形状表达状态。
- 关闭分享弹窗支持 Escape；弹窗打开后焦点到关闭按钮，Tab 在弹窗内循环，关闭后恢复先前焦点。
- `prefers-reduced-motion: reduce`（用户在系统中要求减少动画）时，取消空盘持续旋转、拖动惯性和 600ms 以上的揭示动画，保留即时状态变化。
- 声音默认关闭；MVP 不加载音频。以后若加入音效，必须有显眼的静音开关、系统减少动效/声音偏好处理和授权记录。

## 第六部分：视觉设计系统

### 整体气质和设计关键词

整体采用“夜观星象的工作台”气质：深色背景承托细金线，盘面像一个可阅读的仪器，信息以少量印章和注脚出现。设计关键词具体化为：**深墨底、细金线、低饱和五行色、留白、圆环、点线星图、纸张式卡片**。禁止使用高饱和霓虹、密集表格、红色吉凶警报和仿古插件式边框。

### 配色规则和初始色板

| 用途 | 初始色 | 规则 |
|---|---|---|
| 页面背景 | `#111820` | 全局深色背景，不用纯黑，避免大面积刺眼对比 |
| 卡片背景 | `#172027` | 比背景略亮，卡片之间用边框区分 |
| 主文字 | `#F1EDE2` | 主要正文和标题，确保高对比 |
| 次文字 | `#A6AAA3` | 注释和辅助描述，不承载唯一信息 |
| 金线强调 | `#D4AF37` | 盘环、按钮焦点、关键分隔线，少量使用 |
| 木 | `#5F9F7E` | 生长和舒展的视觉提示 |
| 火 | `#E06B55` | 行动和热烈，不用于错误唯一标记 |
| 土 | `#D5AE67` | 主色和稳定状态 |
| 金 | `#E9E0C9` | 边界和收束 |
| 水 | `#6895A8` | 流动和深度 |

### 字体、尺寸和组件规则

- 标题使用设备可用的宋体/衬线字体回退链，正文使用系统无衬线字体；不引入未经授权的远程字体。
- 页面标题建议 32–48px，详情标题 28–36px，正文 15–17px，注脚 12–13px；移动端标题至少 28px、正文不小于 15px。
- 基础间距用 4px 倍数，页面内边距 20–32px，卡片内边距 20–28px，主按钮高度不低于 44px。
- 卡片圆角 12–18px；输入框 10px；盘环保持圆形，不给每个圆环加单独大阴影。
- 阴影只用于弹窗和悬浮卡：`0 16px 48px rgba(0,0,0,.28)`；盘面使用低透明度描边替代厚重阴影。
- 图标用线性 SVG，线宽 1–1.5px，端点圆润；插画沿用白描线、云纹和星点连线，不混用卡通、照片和 3D 图标。
- 所有按钮、卡片、详情页的标题层级、边框颜色和焦点环必须统一；禁止某个模块自创一套颜色语法。

### 动效和声音

- 盘面旋转过渡 280–600ms，使用平滑缓动；结果揭示可用 300ms 的透明度和描边变化。
- 进入页面不自动播放声音，默认不开启任何音频。
- 减少动效时直接显示最终位置，不能因为动画被禁用而隐藏结果或影响操作。
- 动效用于表达“生成、打开、返回”三个状态，不用于持续吸引注意力；不使用无限闪烁。

## 第七部分：技术路线

### 方案 A：最低复杂度、最适合先做原型（推荐）

- **前端技术**：原生 HTML、CSS、JavaScript；HTML 是页面结构，CSS 是样式，JavaScript 是交互和计算；SVG 是可缩放的矢量图，用于盘面、雷达和命纹。
- **是否需要框架**：不需要。框架是帮助组织大型前端代码的工具，当前页面数量和数据量还不值得引入。
- **是否需要后端**：不需要。后端是运行在网站服务器上的程序；当前没有账号、实时数据或多人同步需求。
- **是否需要数据库**：不需要。结果和反馈放在浏览器 `localStorage`；正式收集反馈前由用户主动下载 JSON。
- **是否需要账号**：不需要，减少注册阻力和隐私责任。
- **是否需要外部 API**：不需要；历法数据先以可审查的本地静态文件提供。
- **数据存放**：`src/data/` 和 `src/core/`；视觉规则在 `src/styles.css`；浏览器保存最近结果。
- **离线能力**：首次在线打开后，Service Worker 可缓存入口和本地资源；直接双击文件不代表离线缓存已启用。
- **部署**：把整个目录上传到支持静态文件的网站；本机优先运行 `npm start` 使用项目自带的 Node 内置静态服务器（Node.js 是运行 JavaScript 的工具），若没有 Node.js 再运行 `python -m http.server 4173 --directory D:\璇玑`。
- **维护难度**：低。负责人主要维护内容来源、样例和 CSS 变量。
- **预计成本**：原型阶段可为 0 元软件成本；后续成本主要是域名、静态托管和人工内容核验。
- **主要风险**：算法近似、浏览器下载/离线差异、缺少多人反馈，不适合把第一版宣传成正式服务。

### 方案 B：适合后续正式扩展的渐进路线

- **前端技术**：当页面超过约 10 个、组件重复明显时，再考虑 Vite（前端构建工具）加 TypeScript（带类型检查的 JavaScript）或轻量框架。迁移应从现有纯函数和数据文件开始，不重写产品逻辑。
- **是否需要框架**：可以需要，但必须由页面复杂度和测试成本触发，而不是为了“看起来专业”。
- **是否需要后端**：只有用户明确需要跨设备同步、公开反馈统计或团队内容管理时再加入一个小型 API（程序之间交换数据的接口）。
- **是否需要数据库**：只有需要多人数据和版本管理时加入托管数据库；先设计最小字段和删除机制。
- **是否需要账号**：跨设备同步或用户主动收藏时再加入，默认匿名体验保持不变。
- **是否需要外部 API**：正式天文历算若无法在本地维护，可选择有稳定文档、价格、隐私和离线降级的服务；密钥不能写在浏览器代码中。
- **数据存放**：可核验的基础表仍在仓库，服务器只保存经用户同意的必要数据；所有字段写入保留期和删除方式。
- **离线能力**：保留静态核心体验；登录或远程数据失败时仍能看已缓存的本地结果。
- **部署**：前端静态托管，后端和数据库分开部署，添加日志、备份和回滚；需要负责人准备域名、托管账号和隐私政策。
- **维护难度**：中到高，增加安全更新、数据库备份、账号找回、费用监控和客服责任。
- **预计成本**：从低额域名/托管费用上升到持续服务器、数据库、API 调用和人工审核费用，不能在没有用户证据前精确报价。
- **主要风险**：过早引入账号、服务器或 API 会扩大攻击面和合规范围，也让离线原型无法快速迭代。

### 推荐结论

推荐方案 A。当前要验证的是核心体验和文化边界，不是规模化数据服务。方案 B 只作为“触发条件明确后的迁移路线”：至少完成 3–5 名真实用户试用、基础历法样本核验、稳定的内容来源表，并确认存在跨设备或团队维护需求，才开始增加框架、后端或数据库。

## 第九部分：数据、内容与版权

### 必须准备的数据

- 一个固定样例：姓名“知微”、日期 `2000-01-01`，用于演示和自动检查。
- 三柱基础映射：天干、地支索引、五行对应关系和版本号。
- 五行颜色、标签、意象短句；每句由项目负责人审阅。
- 命纹算法版本和输入字段说明，确保相同输入可复现。
- 当前星官演示表和节气近似表，并在每条记录中标记“试验/近似”。

### 可以先手工整理的数据

早期只整理 10–20 个代表日期作为样本，不必一次建立完整历史数据库。每条样本至少包含：输入日期、预期年柱/月柱/日柱、计算口径、来源、核验人、核验日期、争议备注。负责人可以先用表格编辑，再由 AI 转成 JSON；转换后要抽查原表和页面是否一致。

### 可使用公开资料的数据

二十四节气的定义和天文时刻可参考官方公开资料；传统名称本身可作为公共文化名称使用，但具体表格、注释和翻译仍要记录来源。香港天文台页面可支持“节气按太阳黄经每 15°划分、精确时间依年份和时区变化”的说明，不能单独支持项目自创的命理断语。

### 不能直接复制或需确认授权的内容

- 古籍现代译文、完整诗诀、商业网站的星官释义、图片、字体文件、音频和第三方排盘表不能直接复制。
- 《灵枢》或其他古籍原文可以研究，但引文长度、版本、译注和使用场景要由负责人逐条核对；产品文案应优先用自写摘要并标注“产品化解释”。
- 商业字体、音效库、地图、星表或农历库必须查看许可证、署名和再分发条件；不因为“网上能看到”就认为可以打包。
- 外部 API 的服务条款、调用上限、价格、用户数据处理和停服风险要在决策记录中确认。

### 每条内容如何记录来源

建议字段为：`contentId`、`contentType`、`textOrValue`、`sourceTitle`、`sourceUrlOrBook`、`editionOrVersion`、`license`、`checkedAt`、`reviewer`、`certainty`、`disputeNote`、`productInterpretation`。页面只展示用户需要的简短来源说明，完整记录放 `docs/content-sources.md`。

### 数据错误如何发现和修正

1. 用至少两份独立公开资料核对关键规则，优先核对边界日期和容易混淆的样本。
2. 把预期结果写成自动检查，避免只看页面颜色。
3. 发现错误时先保留旧版本和错误样本，记录原因、修正人和日期，再更新数据。
4. 如果争议无法解决，页面显示口径选择或“资料待核验”，不要用随机结果掩盖。

### 历史、传统文化、术数或科学内容的分层

| 层级 | 当前处理方式 |
|---|---|
| 可确定事实 | 例如节气的太阳黄经定义、页面实际使用的输入字段、算法版本；有来源就写出处。 |
| 合理解释 | 例如用“木”描述生长意象；必须写成文化隐喻，不当作测量。 |
| 学术争议 | 例如年柱按立春还是春节、二十八宿按农历还是公历对应；在页面注明口径和争议。 |
| 产品化演绎 | 命纹形状、五行配色、星官短文、阴阳滑杆标签；必须标明为项目设计。 |
| 不能作为现实建议的内容 | 疾病、寿夭、婚姻成败、投资、法律、心理诊断和任何需要专业资格的决定。 |

## 第十部分：开发阶段与里程碑

时间按一名负责人配合 AI 工具估算；如果负责人每天只能投入 1 小时，时间可按 2–3 倍延长。每阶段完成后要留下截图、检查结果或决策记录，不以“代码看起来差不多”为完成标准。

### 阶段 0：确认范围和素材

- **目标**：冻结最小切片、样例、免责声明和来源表。
- **任务清单**：负责人读创意文档并圈出必须/延后/不建议项；确认一个样例日期；准备 10–20 个核验样本；确认是否接受本地保存。
- **负责人**：负责人做价值和内容判断；AI 整理表格、发现冲突并写风险；开发工具只检查目录和现有入口。
- **预计时间**：1–2 天。
- **依赖条件**：有创意文档、当前目录和一个能做决定的人。
- **完成标准**：一页范围表、来源登记表有第一批记录、最多 5 个待确认问题得到回答或被标记为假设。
- **不能提前做的事情**：不能先做大运、合婚、账号、支付或完整古籍数据库。
- **可能问题**：负责人想保留所有创意；先用“后续版本清单”记录，不把它们塞进 MVP。

### 阶段 1：视觉方向和可点击原型

- **目标**：不用真实复杂算法，也能点击完成首次建立—输入—今日观象—日志—七日复盘路径。
- **任务清单**：确定工作台侧栏、今日表单、时间线、复盘卡片、色板、字体回退和按钮文案；用一个固定样例制作页面；在电脑和手机宽度检查布局。
- **负责人**：负责人确认审美和文案；AI 生成 HTML/CSS/SVG；开发工具运行本地服务器并截图/检查。
- **预计时间**：2–4 天。
- **依赖条件**：阶段 0 的范围、一个样例和色板。
- **完成标准**：不用解释代码，负责人能自己点击完整路径并保存一条记录；核心按钮和返回路径清楚。
- **不能提前做的事情**：不能为了“像产品”先接外部字体、音效、天文 API。
- **可能问题**：盘面漂亮但用户不知道下一步；让“今日观象”成为默认入口，增加具体记录示例，减少装饰。

### 阶段 2：核心交互原型

- **目标**：验证今日记录、日志编辑、七日复盘、底色下钻、焦点、分享弹窗和错误状态。
- **任务清单**：接入输入校验和三柱近似函数；实现五种镜头和本地日志；实现按日期编辑、导入/导出、删除确认；实现键盘入口、Escape 关闭、焦点恢复和盘面拖动。
- **负责人**：负责人按测试清单操作；AI 编写小步修改和可读报告；开发工具运行 `npm test`、`npm run http-check`。
- **预计时间**：2–5 天。
- **依赖条件**：阶段 1 的页面结构稳定。
- **完成标准**：示例和真实日期都能生成结果；用户能在 3 分钟内保存一条记录；日志和七日复盘显示结果；错误不丢输入；刷新/重开能恢复；分享下载不是空文件。
- **不能提前做的事情**：不能把“能计算”扩大为“计算正确无误”；正式历法仍是下一阶段核验任务。
- **可能问题**：文件双击时模块不加载；用本地静态服务器，不把浏览器限制当作算法故障。

### 阶段 3：MVP 开发

- **目标**：把桌面工作台最小切片整理成可反复启动、可审查来源、可部署的 Windows Alpha。
- **任务清单**：整理 `src/core`、`src/data` 和本地日志格式；补充来源注脚；固定颜色变量；加入 Electron 固定本地协议、桌面检查和 Windows 启动说明；把三个 V2 切片加上明显试验标签或开关。
- **负责人**：负责人确认哪些文案可公开；AI 实现和解释每个改动；开发工具执行测试、静态资源检查和构建演练。
- **预计时间**：3–7 天。
- **依赖条件**：至少一个可用浏览器环境和阶段 2 的通过记录。
- **完成标准**：新电脑按 README 能启动；桌面端能完成建立资料—今日记录—日志—复盘—重开恢复；网页预览在电脑和手机可完成基础路径；所有近似算法和来源状态写在页面及文档中。
- **不能提前做的事情**：不能发布“正式预测服务”或收集真实用户敏感资料。
- **可能问题**：功能越加越多；每次新增需求都必须写到 V2/V3，并说明不进入当前验收。

### 阶段 4：测试与修正

- **目标**：发现 Windows 桌面窗口、重开恢复、日志备份、移动预览、下载和理解偏差。
- **任务清单**：运行自动检查；在至少一台 Windows 电脑走通建立资料—今日记录—日志—复盘—重开；在一部手机检查网页降级；让 3–5 名试用者填写反馈；逐条修复 P1（阻断流程）和 P2（明显体验/无障碍问题）。
- **负责人**：负责人安排试用并保留匿名记录；AI 分析反馈和修复代码；开发工具重跑检查并记录版本。
- **预计时间**：3–7 天，取决于试用者反馈。
- **依赖条件**：可运行的 Electron 开发环境、可分享的网页预览或内网静态服务器、试用记录模板。
- **完成标准**：没有已知阻断错误；用户能说出这是文化体验并在 3 分钟内保存记录；日志导入/导出文件可打开；减少动画、键盘和移动布局通过检查。
- **不能提前做的事情**：不能用 AI 自己“模拟用户喜欢”，也不能在没有反馈时决定扩大 V2。
- **可能问题**：用户把近似星官当成事实；优先改标题、注脚和入口层级，而不是增加更多解释。

### 阶段 5：部署和发布准备

- **目标**：让不懂代码的人能启动和检查 Windows 桌面 Alpha，同时保留网页预览。
- **任务清单**：确认 Electron 依赖；依次运行 `npm run verify`（串联构建、桌面壳、方案、核心烟测、发布和 HTTP 检查）；启动 `npm run desktop:dev` 验证窗口；再决定是否需要静态托管；核对隐私、版权、免责声明和版本号。
- **负责人**：负责人决定是否公开；AI 生成发布清单和排错说明；开发工具上传或预览（只有得到明确发布授权时才进行上传）。
- **预计时间**：1–3 天。
- **依赖条件**：阶段 4 通过，正式域名和托管策略明确。
- **完成标准**：Electron 窗口使用固定本地协议启动，核心工作台可用且不加载远程资源；网页预览的脚本、样式、数据、manifest 和 Service Worker（若启用）返回正确内容；所有页面仍标注原型限制。
- **不能提前做的事情**：不能绑定付费 API、开启用户账号或自动上报反馈。
- **可能问题**：子路径部署导致绝对路径失效；用相对路径和发布后的真实地址逐项检查。

### 阶段 6：真实用户试用与迭代

- **目标**：用小样本决定核心体验是否值得继续，而不是立即扩张内容。
- **任务清单**：招募 3–5 名目标 Windows 用户；记录首次完成时间、是否完成今日记录、是否在第三天回来、是否理解边界、是否愿意保存/分享、最困惑入口；每轮只改一个主问题；对比修改前后反馈。
- **负责人**：负责人做最终审美、文化和优先级判断；AI 汇总匿名反馈并提出小改动；开发工具实现、测试和生成版本记录。
- **预计时间**：每轮 1–2 周。
- **依赖条件**：阶段 5 的可访问原型、用户同意和匿名记录表。
- **完成标准**：至少有一轮真实记录；半数以上试用者能在 3 分钟内完成第一条记录；至少两人愿意在第三天回来；能用证据决定保留/隐藏 V2 试验；确定下一轮一个主要目标。
- **不能提前做的事情**：不能把 3–5 人反馈当成市场规模证明，也不能据此声称算法正确。
- **可能问题**：反馈互相矛盾；按“核心流程完成率”和“误解风险”排序，审美偏好留给后续迭代。

## 第十一部分：验收标准

下面每条都可以由负责人逐项勾选；“通过”应附浏览器、设备、日期和必要截图。

### 功能是否完成

- 首次打开桌面客户端后，用户在 30 秒内能找到“开始建立工作区”；已有资料时直接进入“今日观象”。
- 只填公历生日、不填称呼时，可以生成完整的核心结果。
- 填写空日期、非法日期、未来日期时，表单显示明确提示并保留其他输入。
- 示例数据每次生成相同的三柱、五行主色和命纹。
- 总盘可通过鼠标和触摸水平拖动，点击文字入口可进入对应详情。
- 详情页能返回总盘；分享弹窗能复制摘要、下载 SVG 或打开打印。
- 刷新页面后最近一次结果保留；点击清除后刷新不再恢复。
- 建立工作区后，用户在 3 分钟内能选择一个行动镜头、写下一件事并保存今日记录。
- 保存后“观象日志”能显示日期、镜头、心境、精力、专注、完成状态和文字内容。
- “七日复盘”在 0 条记录时显示空状态，在 1 条以上记录时显示真实记录数和统计值，不生成伪造趋势。
- 日志导出文件可以被 JSON 解析；导入同一文件后记录不会重复增加；删除单条记录后刷新不再显示。
- 关闭并重新打开 Windows 客户端后，个人底色和日志记录仍能恢复。
- V2 三个试验页都显示口径和非正式结论说明。

### 视觉是否达到目标

- 首页、总盘、详情页都使用同一组背景、正文、强调色和圆角规则。
- 盘面环线和命纹在 375px 宽度仍清晰，不被文字覆盖。
- 五行主色变化不改变文字可读性，也不把颜色作为唯一状态信息。
- 未授权字体、图片或音频未被打包。

### 交互是否顺畅

- 用户无需猜测下一步；每个页面有一个明显主按钮。
- 失败提交不把用户送回首页，也不清除已填内容。
- 分享弹窗支持关闭按钮、背景点击和 Escape；关闭后焦点回到原按钮。
- 下载链接在点击后至少保持一段时间再释放对象 URL，生成的文件不为空。

### 移动端是否可用

- 在约 375px 宽度下没有横向滚动条。
- 触摸拖拽盘面不会让页面卡死或误触详情入口。
- 表单和主要按钮在软键盘出现时仍能滚动到。
- 弹窗可滚动，关闭按钮不被屏幕边缘遮挡。

### 电脑端是否可用

- 在约 1280px 宽度下盘面、文字和按钮不失真。
- 鼠标拖动盘面后松开，页面仍可点击文字入口。
- 打印预览不显示不必要的导航和深色遮罩。

### 加载速度和性能

- 在本地静态服务器首次打开后 3 秒内出现首页主要内容（测试设备和网络要记录）。
- 首版没有大图片、自动音频或持续高频动画。
- 减少动效设置下不持续旋转，CPU 占用没有明显异常升高。
- 缺失脚本不会被 Service Worker 以 HTML 首页错误替代。

### 错误处理

- JavaScript 未加载时页面有可读的启动提示或 README 指引。
- 本地存储损坏时能清除失效记录并回到首页，不显示半截结果。
- 剪贴板不可用时显示手动复制提示，下载和打印仍可尝试。
- 资源请求失败时只对导航请求使用离线首页回退，脚本和样式失败要保留真实错误。

### 内容和数据准确性

- 三柱、五行和节气页面明确标出“近似/试验”状态，未核验内容没有正式口吻。
- 至少 10 个样本完成双来源或人工核对，差异有记录。
- 每个自写判语都有审核人和版本；不出现疾病、寿夭、投资等现实断言。

### 版权和来源

- 每一条外部数据、图片、字体、音频和古籍解释都有来源、版本、许可证或“未使用”记录。
- 仓库中没有不能确认授权的商业素材。
- 分享卡只包含项目自绘图形和可公开文字。

### 隐私与安全

- 姓名和生日只在本机处理，不自动上传、不写入 URL、不发送外部 API。
- 反馈 JSON 只有用户主动下载，不包含未同意的浏览器信息。
- 清除按钮能删除本地 profile 和反馈记录，页面给出结果确认。

### 无障碍

- 键盘用户能从首页完成输入、生成、下钻和分享。
- 输入错误使用文字和 `role=alert`/状态提示，不只使用颜色。
- 文字与背景达到 WCAG AA 目标，焦点环清楚。
- 屏幕阅读器能读到盘面替代文本、按钮名称和弹窗标题。
- `prefers-reduced-motion` 开启后，结果和交互仍完整可用。

## 第十二部分：风险、成本与取舍

### 风险矩阵

| 风险 | 发生原因 | 影响 | 概率 | 规避方法 | 出现后的补救 |
|---|---|---|---|---|---|
| 技术风险 | 负责人直接复制复杂代码，状态和路径难以维护 | 页面无法启动或改一处坏多处 | 中 | 保持原生小模块；每次只改一个可验证点；运行自动检查 | 回退到上一个通过版本，先恢复核心流程再加功能 |
| 内容生产风险 | 十二席模块需要大量文案和资料 | 内容拖慢开发，出现空泛断语 | 高 | MVP 只写三柱、五行、命纹；每条文案人工审核 | 删除未审核内容，显示“资料待核验” |
| 数据准确性风险 | 近似节气表、日柱和星官口径不完整 | 用户误信错误结果 | 高 | 页面标注近似；建立样本和来源门槛 | 暂停公开传播，替换数据并在变更记录中说明 |
| 版权风险 | 直接复制古籍译文、诗诀、图片、字体或音频 | 下架、索赔和声誉损失 | 中 | 自绘、自写、系统字体；逐条登记许可证 | 立即移除争议素材，改用自写摘要并咨询权利人 |
| 性能风险 | 过早加入 Canvas、音频、复杂动画 | 老手机卡顿或耗电 | 中 | 小型 SVG；减少动画；先测低端设备 | 关闭动效和 V2 入口，保留文字流程 |
| 移动端兼容风险 | 触摸事件、日期控件、下载在浏览器不同 | 手机无法拖动或保存 | 中 | 至少一台 iOS/Android 实测；提供文字入口和打印替代 | 降级为点击/静态盘面，修复后再开放拖拽 |
| 用户学习成本 | 术语和盘面视觉没有说明 | 用户不知道如何开始或误解结论 | 中 | 示例数据、文字入口、短注脚、首次提示 | 删除装饰和术语，重写首屏和按钮 |
| 范围失控 | 把创意模块表当作第一版合同 | 时间和成本不可控 | 高 | 每个新增需求写入 V2/V3，必须说明替代和验收 | 冻结新功能，恢复最小切片里程碑 |
| 后续维护风险 | 内容和算法没有版本、来源和负责人 | 修正错误时无法追溯 | 中 | 来源登记、变更日志、样本测试 | 建立责任人和数据版本，撤回不明结果 |
| AI 内容不稳定 | AI 自动生成断语、资料或代码出现幻觉 | 事实错误、伦理和版权问题 | 中至高 | AI 只能整理候选；负责人审核事实、文案和审美 | 标记不确定内容，停止自动发布，回到来源核对 |
| 隐私与合规风险 | 后续接账号、统计或外部 API 时扩大数据范围 | 数据泄露和告知义务增加 | 低（MVP）/高（扩展后） | MVP 不上传；扩展前做字段、同意、删除和安全设计 | 关闭远程功能，通知用户并按记录处理数据 |

### 三种预算级别

预算不是报价；真正成本取决于负责人投入时间、是否需要资料专家、是否购买域名/托管、是否使用付费历法或 API、是否请设计和测试人员。

1. **极简验证版**：使用当前原生 JS/SVG、系统字体、本地静态服务器和免费或已有静态托管。成本主要是负责人时间，可能只有域名和少量托管费用。目标是完成一个可点击切片和 3–5 人试用，不购买数据库、账号、API、商业素材。
2. **可公开试用版**：在极简版基础上加入 HTTPS 静态托管、正式域名、基础访问统计（必须匿名且先确认隐私）、更完整的来源核对和跨浏览器测试。成本来自域名/托管、人工核验、测试设备和可能的设计协作；仍不需要后端。
3. **正式产品版**：可能包含经过核验的完整历法数据、内容编辑流程、账号或跨设备同步、服务器、数据库、监控、备份、客服和法律/隐私审查。成本取决于数据授权、开发者人数、服务调用量和维护年限，必须在真实用户需求和范围确认后单独估算。

需要以后确认的项目包括：是否公开域名、是否收集匿名统计、正式历法由谁核验、哪些古籍/字体/音频获得授权、是否允许跨设备保存、是否需要专业内容顾问，以及发布地区的隐私和消费者保护要求。

## 第十三部分：第一周具体行动清单

第一周目标是得到一个可以点击、可以判断方向是否正确的原型，不是写完所有代码。每天最多三项。

### 第 1 天：冻结范围

1. **事情**：在创意文档的模块表旁写上“核心、V2、V3、暂不做”。**操作方式**：只保留三柱、五行、命纹、分享和隐私为 MVP；把大运、合婚、称骨、五格等移入后续表。**完成标志**：形成一页范围表。**做不到的替代**：用本方案第二部分的表直接作为冻结版本。
2. **事情**：确认免责声明和三条不能做的现实建议。**操作方式**：把“文化体验、不构成现实建议、不自动上传”放到首页、详情页和页脚。**完成标志**：负责人逐句确认。**替代**：暂时使用当前原型已有文案，不自行增加断语。

### 第 2 天：准备样例和来源

1. **事情**：确定一个示例输入和 10 个核验日期。**操作方式**：记录日期、当前程序结果、预期来源和待核对项。**完成标志**：表格或 Markdown 清单可打开。**替代**：先使用 `2000-01-01` 和现有自动检查，明确写“待核验”。
2. **事情**：建立内容来源登记。**操作方式**：把节气官方链接、项目自绘图形、自写文案、系统字体分别登记。**完成标志**：每类内容有来源或“未使用第三方素材”。**替代**：复制 `docs/content-sources.md` 的表并补核验日期。

### 第 3 天：确认视觉方向

1. **事情**：在浏览器打开首页、输入页、总盘页。**操作方式**：双击 `启动璇玑.bat` 或运行本地静态服务器，在电脑和手机宽度查看。**完成标志**：能用一句话描述主色、盘面和按钮是否协调。**替代**：若服务器打不开，先运行 `npm test` 检查文件，再请 AI 只修启动问题。
2. **事情**：选定一套色板和字体回退。**操作方式**：只使用本方案第六部分初始值，不同时试十套风格。**完成标志**：负责人确认“玄青夜景 + 金线 + 低饱和五行色”。**替代**：保留当前 `styles.css`，把争议写入决策记录。

### 第 4 天：走通核心交互

1. **事情**：完成首次建立 → 今日观象 → 日志 → 七日复盘的点击路径。**操作方式**：使用示例资料，选择一个镜头，写下“完成第一条记录”，保存后查看统计。**完成标志**：没有死路、空页面或无法返回。**替代**：先使用开发机样例，只验工作台闭环。
2. **事情**：验证底色详情、拖拽和键盘。**操作方式**：鼠标、触摸（如有设备）、Tab、Enter、Escape 各试一次。**完成标志**：文字入口可代替盘钉，分享弹窗可关闭，今日记录不丢失。**替代**：若触摸异常，保留静态盘面和文字按钮，记录为修复项。

### 第 5 天：验证保存与分享

1. **事情**：验证日志保存、编辑、删除和重开恢复。**操作方式**：写一条记录、改日期补写第二条、导出 JSON、删除一条、关闭并重开客户端。**完成标志**：日志数量和文字与操作一致，重开后仍保留剩余记录。**替代**：若文件选择器不可用，先验保存/重开，把导入标为待复测。
2. **事情**：下载和打印分享卡。**操作方式**：下载 SVG，用文本编辑器或浏览器打开；再打开打印预览。**完成标志**：文件不是空白，内容与页面一致。**替代**：若下载不稳定，先使用打印保存路径并记录浏览器型号。

### 第 6 天：小范围试用

1. **事情**：邀请 1–2 名熟悉项目的朋友完成任务。**操作方式**：只给任务“生成一张盘并说出你理解的产品是什么”，不先讲答案。**完成标志**：记录完成时间、困惑点、是否愿意保存/分享。**替代**：若没有试用者，负责人自己用“第一次接触者”视角完成 user-test 表，但不能算真实证据。
2. **事情**：修一个最高优先级问题。**操作方式**：只改阻断完成或导致误解的一项，改前后运行自动检查。**完成标志**：变更记录写明原因和验证方式。**替代**：如果没有明显问题，冻结代码，不增加新功能。

### 第 7 天：形成阶段结论

1. **事情**：运行 `npm run build`、`npm run plan-check`、`npm test`、`npm run release-check`、`npm run http-check`。**操作方式**：在项目目录打开终端执行命令；它们分别检查发布文件、方案结构、核心流程、发布资源和 HTTP 返回。**完成标志**：保存命令输出和日期。**替代**：若某个命令失败，先按错误提示修复或记录，不用手工“跳过”。
2. **事情**：写一页“继续/修改/暂停”结论。**操作方式**：回答核心流程是否完成、用户是否理解边界、是否愿意保存/分享、下一周只做什么。**完成标志**：下一步最多一个主要目标。**替代**：没有足够反馈就写“继续小范围试用”，不要假设市场验证通过。

## 结尾决策清单

### 推荐的 MVP 范围

首页、输入页、今日观象、观象日志、七日复盘、我的底色、命盘/五行/命纹详情、分享弹窗、说明与隐私页。用户输入称呼和公历生日后，能在 3 分钟内选择木/火/土/金/水之一作为行动镜头，记录一件事、精力、专注、心境和完成状态，之后按日期回看并导出 JSON。星官、阴阳四维、生日节气只作为底色中的明确 V2 试验，默认不能被解释为正式结论；复盘只做描述统计，不做预测或因果判断。

### 推荐的技术路线

主要产品采用“原生 HTML/CSS/JavaScript/SVG 页面 + Electron Windows 桌面壳”的方案 A：静态数据、无账号、无后端、无数据库、无外部 API，使用固定 `xuanji://` 本地协议保存本机结果，桌面离线不依赖 Service Worker。网页静态服务器和 Service Worker 只保留为开发预览和备用体验。等桌面 Alpha、真实试用和资料核验通过后，再按方案 B 评估安装包、签名、更新和 Tauri 体积优化；没有新的用户证据，不升级复杂架构。

### 第一阶段原型页面清单

Windows 桌面窗口内的首页、输入页、今日观象、观象日志、七日复盘、我的底色、六字命盘详情、五行气象详情、命纹详情、分享弹窗、说明与隐私页；V2 星官/阴阳四维/生日节气页面作为可关闭试验入口。网页版本只用来预览同一套页面。

### 当前最重要的三个决策

1. 是否把“输入—今日观象—记录一件事—七日复盘”确认为唯一 MVP 主线，把总盘和命纹降为个人底色。
2. 是否接受当前三柱、星官和节气只作为有来源说明的近似/演示，正式发布前不作预测宣传。
3. 是否坚持第一阶段无账号、无上传、无后端、无外部 API，并用 3–5 名真实用户反馈决定下一步；安装包和签名必须等桌面 Alpha 通过后再决定。

### 当前最危险的三个假设

1. 用户会因为命纹、主色和可旋转盘面而愿意完成输入并分享。
2. 用户能理解“文化演绎”与“正式结论”的差别，不会把近似历法或 V2 演示当作现实建议。
3. Electron 固定本地协议和原生 SVG 能在目标 Windows 电脑稳定完成拖动、下载、重开恢复和焦点交互；网页预览的手机和浏览器兼容只作为辅助证据。

### 需要我确认的问题（最多 5 个）

1. MVP 是否只面向中文 Windows 桌面客户端，网页只作预览，并只接受公历日期，不在第一版加入农历/性别/时辰输入？
2. 三个 V2 试验入口是默认显示并标注，还是在第一轮真实试用中默认隐藏？
3. 第一轮真实试用能否安排 3–5 名目标用户，并允许收集匿名的完成时间、困惑点和分享意愿？
4. 正式历法和传统内容是否有指定顾问、书目或机构作为核验负责人？
5. 桌面 Alpha 通过后，是否需要生成 Windows 安装包；在此之前是否继续只做本地开发，不购买签名证书、账号系统或收费服务？

### 现在不要做什么

现在不要做完整十二席模块、生肖纳音太岁、五格吉凶、大运、合婚、称骨、二十五人对照、双雷达、五音音效、PNG 专用导出、账号、支付、社区、后台、实时天文 API、自动上传反馈、Windows 安装包、自动更新或远程日志；也不要把近似算法写成正式预测服务，或在没有来源和授权记录时加入古籍、图片、字体、音频。
