# 璇玑「观象记录」价值闭环设计

版本：v0.2｜日期：2026-10-05｜状态：桌面 Alpha 已实现第一轮闭环，等待目标电脑和真实用户验收

这份补充方案解决当前原型的核心问题：用户生成一张盘以后，体验很快结束，结果没有被用于任何持续的事情。璇玑的桌面客户端应从“一次性生成个人盘”升级为“以个人盘为入口的本地观察记录工具”。盘面负责提供文化视角和视觉锚点，记录、回看和对照才是可重复使用的价值。

> **实现状态（2026-10-05）**：当前代码已完成第一轮可运行闭环：今日观象、五行行动镜头、场景、事实/感受/下一步字段、观象日志时间线、七日描述统计复盘、固定本地协议下的重开恢复、JSON 导出/导入预览确认、单条删除和 5 秒撤销、两条记录字段对照。更完整的导入字段提示、草稿恢复和 Markdown 导出仍保留为后续小阶段；文档中的后续条目不视为已完成承诺。

## 一、产品改动结论

### 新的一句话定位

璇玑是一款把传统时间符号变成个人观察提示，并帮助用户在本机记录、回看和整理生活观察的桌面工具。

### 用户真正得到的东西

用户每次打开客户端都可以完成一件具体的小事：记下一个发生过的场景、自己当时的感受、正在尝试的行动，之后回来看自己写过什么。系统只整理用户写下的内容，不替用户判断因果，也不把五行或星官包装成预测。

### 必须保留的边界

- 盘面、五行、命纹是文化演绎和写作提示，不是事实判断、心理诊断或现实建议。
- “对照”只比较用户自己选择的两条记录，不能生成“你的命局导致了某种结果”之类的因果结论。
- 所有记录、草稿、导出和导入均在本机完成。没有账号、后端、统计脚本、外部 API 或自动上传。
- 用户可以一条一条删除，也可以清空全部记录；任何操作都不能静默丢失数据。

## 二、最小但有实际使用价值的功能切片

第一阶段只做一个可反复使用的闭环：

`生成个人盘 → 选择一个关注主题 → 记下一件具体发生的事 → 写下一个小行动 → 以后在时间线上回看 → 选两条记录做人工对照 → 导出自己的记录`

### MVP 必须包含

1. **记录入口**：总盘页有“写下这次观察”主按钮；记录页也有“新建记录”。
2. **固定主题**：从 8 个低认知成本的主题中选 1–3 个：专注、学习、创作、关系、选择、节奏、情绪感受、其他。主题是索引，不是标签诊断。
3. **事实和感受分开写**：表单分为“发生了什么”和“我当时怎么感受”，避免把主观解释伪装成事实。
4. **一个小行动**：可选填写“接下来想试什么”，便于记录后再次回来；不显示成系统建议。
5. **时间线**：按日期倒序展示记录，显示主题、标题、当天盘面主色和一行摘要；点击进入记录详情。
6. **两条记录对照**：用户手动勾选两条记录，左右显示日期、主题、原文、行动和个人盘面摘要；系统只列“字段不同”，不输出因果或吉凶判断。
7. **本地导出与导入**：导出完整备份 JSON；导出单条或选中记录的 Markdown/纯文本；导入前预览数量和日期，用户确认后合并。
8. **删除与恢复提示**：删除前明确告知影响；删除后提供短暂“撤销”按钮；清空全部记录前要求二次确认并提示先导出。
9. **空状态和样例**：没有记录时显示一个可删除的样例卡，清楚标记为“示例”，让用户知道要写到什么程度。

### 明确不进入 MVP

- 每日自动推送、提醒、连续打卡、积分、排行榜或社区。
- 根据记录自动总结性格、推断命运、预测下周、给出关系/投资/健康建议。
- 云同步、账号、跨设备同步、远程日志、第三方 AI 总结或外部内容 API。
- 模糊的“匹配度”“趋势分数”“吉凶变化”和自动相关性图表。
- 大运、合婚、称骨、五格、完整二十八宿等尚未核验的文化模块。

## 三、记录数据结构

当前 Alpha 用版本化 JSON 保存在固定本地 origin 的 `localStorage` 中，最多保留 365 条轻量记录，超过上限时停止新建并先提示用户导出；不能自动删除最旧记录。记录量或正文长度明显增长后，再迁移 IndexedDB（浏览器内置的大容量本地数据库）。

### 存储键

| 键 | 用途 |
|---|---|
| `xuanji-profile` | 当前个人盘输入和计算结果，已有数据结构继续使用 |
| `xuanji-journal-v1` | 记录集合，结构见下文 |
| `xuanji-journal-settings-v1` | 排序、是否显示样例等本机偏好，不存设备指纹 |
| `xuanji-journal-draft-v1` | 用户主动开始编辑但尚未保存的草稿；关闭窗口后可恢复一次 |

### 单条记录字段

```json
{
  "schemaVersion": 1,
  "id": "rec_20261005_8f3c",
  "createdAt": "2026-10-05T09:30:00+08:00",
  "updatedAt": "2026-10-05T09:42:00+08:00",
  "observedOn": "2026-10-05",
  "title": "第一次使用璇玑",
  "context": "创作",
  "themes": ["创作", "节奏"],
  "whatHappened": "下午整理了展览方案，先做了半小时草图。",
  "felt": "开始时分心，画到第二张草图后比较稳定。",
  "nextAction": "下次先关掉消息通知，再做 25 分钟草图。",
  "reviewOn": "2026-10-12",
  "reviewNote": "",
  "reviewStatus": "待回看",
  "profileSnapshot": {
    "algorithmVersion": "prototype-0.3",
    "dominantKey": "wood",
    "dominantLabel": "木",
    "dominantPercent": 32,
    "scores": {"木": 32, "火": 18, "土": 20, "金": 12, "水": 18}
  },
  "source": "manual",
  "isSample": false
}
```

### 字段规则

- `id` 在本机生成，导入合并时按 `id` 去重；不使用姓名、生日或设备信息生成 ID。
- `observedOn` 是用户选择的观察日期，不强制等于创建日期，允许补记过去的事情。
- `title` 1–40 字；`whatHappened` 1–800 字；`felt` 0–300 字；`nextAction` 0–300 字；超限时在输入框下说明剩余字数。
- `context` 只从日常、工作、学习、关系、创作、选择、休息、其他中选择一个，避免自由分类造成不可用的筛选器。
- `themes` 最多 3 个；用户不选主题也可以保存，但保存按钮需提示“至少选一个主题更方便以后回看”。
- `reviewStatus` 只能是“待回看”“已回看”“不再跟进”；没有自动提醒。`reviewOn` 只是时间线上的一个日期。
- `profileSnapshot` 只保存当次盘面用于回看所需的摘要，不重复保存姓名和完整生日；导出备份可由用户选择是否包含当前盘面摘要。
- `source` 固定为 `manual`，表示内容由用户填写；不允许把 AI 生成的段落伪装成用户观察。
- 所有日期使用 ISO 格式，显示时按本机语言格式化；缺失或非法字段在导入预览阶段拒绝，不部分写入。

### 导出格式和隐私

1. **本地备份 `.xj.json`**：包括记录正文、日期、主题和盘面摘要；默认不含姓名、完整生日、浏览器信息和路径。文件由用户主动保存到自己选择的位置。
2. **阅读版 `.md`**：只包含用户选中的记录正文、日期、主题和行动；默认隐藏盘面摘要，适合自己整理或打印。
3. **导入**：只读取用户主动选择的本地文件；先显示“将新增/覆盖/跳过多少条”，合并前需要点击确认；导入失败时不修改现有记录。
4. **分享**：分享卡继续只显示用户主动选择的内容；新建记录时不自动把笔记写入分享卡。

## 四、页面与用户流程

### 页面层级

```text
首页
└─ 输入页
   └─ 总盘页
      ├─ 盘面详情
      ├─ 观象记录（时间线）
      │  ├─ 新建/编辑记录
      │  ├─ 记录详情
      │  └─ 选择两条记录对照
      ├─ 命纹分享
      └─ 说明与隐私
```

### 流程 A：第一次留下记录

1. 用户生成盘后，总盘页展示主按钮“写下这次观察”，旁边说明“记录你自己的经历，璇玑不替你下结论”。
2. 点击后打开记录表单；日期默认为今天，盘面摘要以只读小卡片展示，不要求用户再次输入生日。
3. 用户选择一个场景和至少一个主题，写一句“发生了什么”；“感受”和“接下来想试什么”可选。
4. 点击保存后显示确认卡：“记录已保存在这台电脑”。按钮为“查看时间线”和“回到总盘”。
5. 若未填写正文，保存按钮不可用并提示示例句；用户可以放弃草稿，系统不生成空记录。

### 流程 B：重复使用

1. 打开桌面客户端，若已有盘面，首页直接显示“继续上次观盘”和“最近一次记录”；两者都能进入时间线。
2. 时间线默认显示最近 20 条，按月份分组；用户可按主题筛选，筛选只改变显示，不修改数据。
3. 点击记录卡进入详情，看到正文、盘面摘要、下一行动和回看日期；用户可编辑、复制为 Markdown、标记已回看或删除。
4. 当 `reviewOn` 到期时只在时间线上显示“可以回看”，不弹窗、不联网、不自动通知。
5. 回看时用户补写 `reviewNote`，状态改为“已回看”；这让记录形成“发生—尝试—回看”的闭环。

### 流程 C：两条记录对照

1. 用户在时间线中点击“选择对照”，最多选两条；底部显示“开始对照”。
2. 对照页左右显示日期、场景、主题、正文、行动和盘面主色，顺序固定，不自动改写原文。
3. 页面仅在字段层面显示差异，例如“主题不同：创作 / 学习”“都有下一行动 / 只有左侧有下一行动”。
4. 末尾提供用户自己填写的“我注意到的不同”文本框；保存后形成一条 `comparison` 本地草稿或直接复制 Markdown。首版可以不把对照另存为新记录。
5. 页面固定提示：“这里展示的是你选择的两条记录，不代表盘面与事件存在因果关系。”

### 流程 D：中断、错误和恢复

- 离开新建表单：保存草稿到 `xuanji-journal-draft-v1`，下一次进入时询问“继续编辑 / 放弃草稿”；草稿最多保留一份。
- 本地存储不可写：进入只读模式，允许查看已有记录，明确提示“无法保存，请先导出或检查磁盘权限”；不假装保存成功。
- 导入文件格式错误：显示具体字段和行号（如果可定位），不覆盖原数据。
- 删除记录：先确认，删除后 5 秒内显示撤销；窗口刷新后不承诺可恢复，所以提示先导出。
- 没有当前盘面但有旧记录：时间线仍可查看；新记录要求先生成盘面或选择“只写记录（无盘面摘要）”。

## 五、低复杂度技术路线

### 首版实现

- 继续使用现有原生 JavaScript、HTML、CSS 和 SVG，不引入 React、数据库、账号或服务端。
- 把记录逻辑放在独立的 `src/core/journal.js`，页面渲染放在 `src/main.js`；字段和固定主题集中到 `src/data/journal.js`。
- `loadJournal()` 负责读取、校验和迁移版本；`saveJournal()` 使用一次性序列化写入；写入前先验证长度和 schema。
- 使用 `crypto.randomUUID()` 生成 ID；不支持时用本机时间和随机数生成，但不包含个人字段。
- 下载使用用户主动点击触发的 Blob；导入使用 `<input type="file">` 和 `File.text()`，文件内容只在渲染进程内解析。
- 桌面客户端继续使用固定 `xuanji://bundle/` origin，因此关闭窗口再打开不会因为随机端口变化而丢本地记录。网页预览可继续使用同一套逻辑。

### 需要的最小文件

```text
src/
  core/
    journal.js          # schema、校验、增删改、导入合并、撤销快照
  data/
    journal.js          # 主题、场景、示例记录和字段限制
  main.js               # 记录页面状态和事件绑定（不把校验规则散落在模板）
  styles.css            # 时间线、表单、对照页的共享视觉变量
docs/
  value-loop-local-journal.md
  content-sources.md    # 继续登记自写文案和图形来源
```

### 低风险迁移顺序

1. 先实现纯函数：默认值、校验、排序、合并和导出文本，写 10 个边界测试。
2. 再加时间线只读页面，用内置样例确认空状态、超长文本和缺失盘面都能显示。
3. 再接入新建/编辑/删除和撤销；确认旧 `xuanji-profile` 仍能正常恢复。
4. 最后接入导入/导出和对照，不在同一个步骤修改排盘算法或视觉系统。
5. 每一步先运行 `npm test`、`npm run desktop-check`，再做桌面窗口手工验收；不为记录功能引入网络依赖。

## 六、可验收指标

这些是第一轮 3–5 人小范围试用的产品验收目标，不是市场规模承诺。由于不做埋点，数据由负责人现场观察或让用户主动下载匿名反馈 JSON 获得。

### 功能验收

- 生成盘面后，用户在 10 秒内能找到“写下这次观察”。
- 新用户不看说明，也能在 3 分钟内保存一条包含日期、场景、主题和正文的记录。
- 关闭并重新打开桌面客户端后，最近 20 条记录仍按日期正确显示。
- 编辑、删除、撤销、按主题筛选均只影响本地数据，刷新后结果一致。
- 导出 JSON 后清空记录，再导入同一文件，记录数量、正文、主题和日期 100% 一致。
- 选择两条记录时，对照页不出现自动“好/坏、适合/不适合、因果、预测”句式。
- 记录页、导出和导入流程不产生网络请求；可以在断网状态下完成。

### 价值验收

- 5 名试用者中至少 4 人能用自己的话说明“这里记录的是我观察到的事”，而不是“软件替我算出了结果”。
- 5 名试用者中至少 4 人完成第一条记录；中位完成时间不超过 3 分钟。
- 一周后至少 3 人愿意再次打开并新增一条记录或回看旧记录；若无人回来，先修改入口和提示，不扩展更多术数模块。
- 至少 3 人能说出一个具体的再次使用理由，例如“记录一次创作状态后下周回看”，而不是“等下一次预测”。
- 至少 4 人能找到导出入口并理解备份文件保存在自己选择的位置。
- 试用中没有人把“主色/五行”当成健康、投资、婚姻或其他现实决策依据；若出现一次，立即修改文案并暂停扩大试用。

### 性能与隐私验收

- 20 条记录在本地打开时间线不超过 1 秒；100 条记录仍能滚动，不发生明显卡顿。
- 单条正文超过限制时不能保存；导入 365 条合法记录不会阻塞界面超过 2 秒。
- 网络断开时，新增、编辑、筛选、对照、导出和导入仍可用。
- 代码和构建产物中没有分析脚本、远程字体、远程图片或第三方接口地址。
- 清除本地观盘记录的操作同时说明是否清除观象记录；两者不能悄悄只清一部分。

## 七、风险与取舍

| 风险 | 影响 | 首版取舍 |
|---|---|---|
| 记录功能变成普通备忘录，失去璇玑特色 | 用户看不出为什么要用璇玑 | 每条记录保留只读的盘面主色/文化摘要，但不让摘要替用户解释生活 |
| 用户把对照当作因果分析 | 伦理和信任风险 | 只做字段差异，固定显示边界文案，不做趋势分数 |
| 记录数据被误删 | 用户失去个人内容 | 删除前确认、导出备份、超过 365 条不静默淘汰 |
| 本地存储空间不足或损坏 | 无法新增/恢复 | 版本化 schema、写入前校验、导出入口、只读降级；V2 再迁移 IndexedDB |
| 表单太长导致用户不愿记录 | 核心闭环失败 | 首版正文只有一个必填框；感受、行动和回看日期可选 |
| AI 文案把用户笔记改成断语 | 失去人的判断 | 首版不接 AI 总结；AI 只能在开发阶段帮助整理字段，不能自动写入记录 |

## 八、后续版本

- **V2**：IndexedDB 大容量存储、记录全文搜索、更多筛选、批量导出、可选的本地提醒（系统通知默认关闭）；先用真实回访证据决定是否需要。
- **V3**：用户明确同意后才评估跨设备同步、加密备份或协作分享；这会引入账号、服务器、隐私和维护成本，不能从 MVP 自然推导出来。
- **不因“功能显得丰富”提前加入**：自动解读、每日运势、社交关系评分、远程 AI、云端画像和广告。

## 九、给开发工具的最小执行指令

> 先阅读 `06-璇玑-创意文档.md`、`docs/初步开发设计整体方案.md`、`docs/desktop-client-plan.md` 和 `docs/value-loop-local-journal.md`。当前目标是把璇玑从一次性盘面增加为本地“观象记录”闭环，不能借机添加账号、后端、API、统计、社区或预测功能。先检查现有 `xuanji-profile` 数据结构，保持旧用户数据可恢复。第一步只实现 `src/core/journal.js` 的版本化纯函数和测试：创建、校验、排序、删除、撤销、导出、导入合并；每完成一步说明改了什么、为什么改、如何验收。第二步再做时间线只读页面，第三步做新建/编辑/删除，第四步做两条记录对照，最后做导入导出。每条记录都要区分“发生了什么”和“我怎么感受”，对照页只能显示用户记录的字段差异，不得生成因果、吉凶或现实建议。所有数据只保存在固定本地 origin；导出必须由用户主动点击，导入必须先预览并确认。遇到失败先解释原因，不用删除旧功能或跳过检查来掩盖问题。
