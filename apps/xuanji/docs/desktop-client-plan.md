# 璇玑桌面客户端形态修订

修订日期：2026-10-05  
适用范围：在现有静态原型基础上，把“桌面客户端”确定为主要产品形态；浏览器版本保留为开发验证和备用体验。

## 一、产品形态决定

璇玑的主要交付物是 Windows 桌面客户端。用户双击图标后看到一个没有地址栏、没有浏览器标签页的应用窗口，在本机完成输入、今日观象、观象日志、七日复盘、底色详情、分享和本地保存。当前 `index.html`、`src/main.js` 和 `src/styles.css` 继续作为界面核心，但不再把“上传网站”当成第一交付目标。

浏览器静态版本仍然保留两个作用：开发时快速查看界面，以及在没有安装桌面客户端时提供只读的备用预览。它不能改变桌面客户端的隐私、启动和发布标准。

## 二、第一版桌面 MVP

第一版桌面客户端只做以下范围：

1. Windows 单窗口启动，默认窗口约 1100×760，最小宽度 860、最小高度 640。
2. 本地加载界面和静态数据，不要求账号、网络、后端、数据库或外部 API。
3. 第一条可重复使用主线是“输入 → 今日观象 → 记录一件事 → 七日复盘”；总盘、命盘/五行/命纹是个人底色与视觉锚点。
4. 用户数据只保存在该客户端的本机应用数据目录；说明页提供清除入口。
5. 分享卡继续支持复制、SVG 下载和系统打印；第一版不接系统相册、云同步或社交分享接口。
6. 初始版本采用手动安装包，不做自动更新、不做托盘常驻、不做开机启动。
7. 窗口关闭后再次打开能恢复最近一次本地观盘和观象日志；清除后不能恢复。

“桌面客户端”不等于把所有桌面能力都加入第一版。文件读写、系统通知、托盘、自动更新、云同步和跨设备账号都推迟到用户验证之后。

## 三、推荐技术路线

### 方案 A：Electron 桌面壳（当前推荐）

- **界面**：继续使用现有原生 HTML、CSS、JavaScript 和 SVG。
- **桌面壳**：Electron 主进程只负责创建窗口、加载本地入口和处理应用生命周期。
- **安全设置**：窗口开启 `contextIsolation`，关闭 `nodeIntegration`，默认启用沙箱；渲染页面不直接接触 Node 文件系统。
- **数据**：第一版继续使用浏览器 `localStorage`，由 Electron 的应用用户目录自动持久化；不新增数据库。
- **网络**：默认不请求互联网；不加载远程脚本、不打开外部页面作为应用内容。
- **打包**：开发模式已通过一次真实 Windows 窗口验证；再做 Windows 安装包演练前，先完成真实用户试用和数据导入/导出边界确认。
- **优点**：负责人和 AI 只需继续使用 JavaScript，迁移现有页面最快，适合先验证桌面体验。
- **代价**：安装包较大，内存占用通常高于系统 WebView；正式发布前必须做签名、更新和漏洞修复流程。

Electron 官方安全文档明确建议关闭渲染器 Node 集成并启用上下文隔离；这些设置必须成为桌面壳的验收条件：[Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)、[Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)。

### 方案 B：Tauri 桌面壳（后续评估）

- **界面**：继续复用现有 HTML、CSS、JavaScript。
- **桌面壳**：使用系统 WebView2，并由 Rust 负责窗口和受控系统能力。
- **优点**：安装包和运行时通常更轻，系统 WebView2 可独立更新。
- **代价**：需要 Rust、Cargo、Windows 构建工具和额外的权限模型；对没有开发基础的负责人更难维护。
- **进入条件**：至少完成一轮真实用户试用、确认需要更小安装包，且有人负责 Rust 构建与签名。

Tauri 官方资料说明 Windows 构建依赖 WebView2，并支持将固定版本运行时随安装包分发；这属于后续正式产品决策，不进入当前桌面 MVP：[Tauri Windows Installer](https://tauri.app/distribute/windows-installer/)、[Tauri WebView 版本](https://tauri.app/reference/webview-versions/)。

## 四、桌面目录建议

```text
desktop/
├─ main.cjs           # Electron 主进程：窗口、生命周期和安全设置
├─ preload.cjs        # 预留受控桥接；当前不暴露文件系统 API
└─ README.md          # 桌面开发、启动和打包说明
```

第一版不把计算逻辑搬到主进程，不建立 `services/`、数据库或 IPC 层。只有确实需要系统能力时，才新增一个最小、可审计的桥接方法。

## 五、桌面启动和发布阶段

### 阶段 D0：桌面形态确认

- 负责人确认 Windows 优先、是否需要 macOS、是否接受较大的 Electron 安装包。
- AI 把当前网页核心体验包装成单窗口桌面壳。
- 通过条件：双击开发启动方式后能看到无地址栏的璇玑窗口，关闭后不会留下服务器进程。

### 阶段 D1：桌面壳原型

- 加入主进程、预加载脚本和单窗口配置。
- 检查本地资源、localStorage、今日记录、日志、七日复盘、SVG 下载和打印是否仍然可用。
- 通过条件：在没有网络时仍能完成记录闭环；开发者工具默认关闭或仅在开发模式打开。当前开发机证据见 [desktop-qa-2026-10-05.md](desktop-qa-2026-10-05.md)。

### 阶段 D2：安装包演练

- 决定打包工具、应用名称、图标、安装目录、卸载行为和版本号。
- 先生成内部测试安装包，不公开分发。
- 通过条件：新 Windows 用户按说明安装、启动、清除数据和卸载；卸载后没有自动上传或残留敏感文件。

### 阶段 D3：桌面用户试用

- 让 3–5 名用户直接使用桌面窗口，不给浏览器替代路径。
- 记录启动时间、核心流程完成率、窗口尺寸、打印和下载问题。
- 通过条件：至少 3 人完成主线；至少 80% 在 3 分钟内保存第一条今日记录；至少 3 人理解这是文化体验。

## 六、桌面验收新增项

- 双击应用图标后 10 秒内出现首页，且没有地址栏、开发者工具或浏览器标签页。
- 断开网络后，应用仍能打开首页并完成核心观盘。
- 应用关闭后没有遗留本项目启动的 Node 或临时服务器进程。
- 应用只能访问本地打包资源；没有未说明的远程请求。
- 清除本地记录后重新启动，个人观盘和本地反馈都不恢复。
- SVG 下载和打印使用系统默认路径时，文件可以打开且不为空。
- 应用窗口缩放到最小尺寸时，主要按钮、输入框和返回路径仍可见。
- 在 Windows 高 DPI 或系统字体放大设置下，文字不被裁切。
- 安装包、图标、版本号和卸载入口都能追溯到来源记录。

## 七、当前不做的桌面能力

暂不做系统托盘、开机启动、自动更新、账号同步、云端备份、系统通知、文件批量导入、社交分享、原生相册写入、远程日志和自动上传反馈。这些能力会增加权限、隐私、打包和维护成本，必须等真实桌面用户需求出现后再单独立项。

## 八、形态变更后的关键决策

1. 桌面客户端是主要交付物，浏览器只是开发验证和备用预览。
2. 当前推荐 Electron 作为第一版桌面壳，Tauri 暂作为后续轻量化评估。
3. 桌面 MVP 仍保持本地优先、无账号、无后端、无外部 API和无自动上传。
4. 在桌面壳和安装包通过内部验收前，不公开宣称已经完成正式桌面产品发布。
