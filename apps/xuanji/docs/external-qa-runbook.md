# 璇玑外部验收运行手册

这份手册只用于完成真实环境验收。它不改变当前算法、范围或隐私设计，也不把负责人自己重复操作当作外部用户证据。

## 一、负责人先准备

1. 在项目目录打开终端：

   ```powershell
   cd D:\璇玑
   npm start
   ```

2. 浏览器打开终端显示的地址，通常是 `http://127.0.0.1:4173/`。如果端口被占用，运行 `npm start -- --port 4174`，再打开 `http://127.0.0.1:4174/`。
3. 如需给同一局域网的手机访问，不能直接使用 `127.0.0.1`；请在负责人确认隐私边界后，用已审核的静态 HTTPS 预览地址进行测试。不要把姓名、生日或反馈上传到未确认的服务。

## 二、电脑验收

使用 Chrome 或 Edge，按顺序完成并勾选：

- 首页能看到“开始观盘”和免责声明。
- 输入“知微”和 `2000-01-01`，在 30 秒内生成总盘。
- 进入命盘、五行、命纹三个详情页，并能返回总盘。
- 打开分享卡，复制摘要，下载 SVG，并用浏览器或文本编辑器打开文件。
- 打印预览能看到分享卡主要内容；取消打印不会破坏页面。
- 刷新后结果仍在；进入阴阳四维，将一条滑杆改为 82，刷新后仍为 82。
- 进入“说明与隐私”，保存一条本地反馈，再点击清除；页面出现清除提示，反馈下载按钮提示没有可下载反馈。

## 三、真实手机验收

在至少一部 Android 或 iPhone 上完成：

- 页面没有横向滚动，文字和按钮可读、可点。
- 能用手指拖动总盘；拖动失败时，文字入口仍能打开详情。
- 日期控件能选择生日，提交后能看到总盘。
- 分享卡能打开；打印或下载失败时，记录手机型号和浏览器版本，不要把失败当成用户问题。

## 四、离线验收

这一步必须在 Chrome 或 Edge 中进行，不能只看 `npm test`：

1. 用本地服务器或 HTTPS 地址在线打开首页，等待页面完全加载。
2. 在开发者工具的 Application/应用面板确认 Service Worker 已注册并缓存资源。
3. 关闭网络或启用 Offline/离线，再刷新页面。
4. 确认首页、样式和 JavaScript 仍能加载；打开一个不存在的脚本地址时，不应得到一份伪装成脚本的 HTML 页面。
5. 恢复网络并再次刷新，确认页面回到正常状态。

若浏览器没有暴露 Service Worker 面板，记录“未验证”及浏览器版本，不要写成“离线通过”。

如果电脑安装了 Microsoft Edge，也可以在项目目录运行 `npm run edge-offline-check`。它会启动临时本地服务器和隔离的 Edge 用户目录，自动检查 Service Worker 激活、离线刷新和缺失脚本不会被 HTML 替换。输出 `PASS` 才能记录为自动化离线通过；输出 `SKIP` 或 `UNVERIFIED` 仍按未验证处理。

## 五、3–5 名真实用户试用

每位测试者只收到一句任务：

> 请用这个页面生成一份属于你的观盘结果，然后告诉我你最想保存或分享的部分。

测试者不应事先听到三柱、五行或命纹的解释。按 [user-test.md](user-test.md) 记录：

- 设备和浏览器；
- 找到开始按钮所需时间；
- 看到总盘所需时间；
- 第一次卡住的位置；
- 是否理解这是文化体验，而非确定性预测；
- 是否愿意保存或分享；
- 自发说出的第一句话、最困惑的词、最喜欢的部分。

通过条件：至少 3 人完成核心流程；至少 80% 在 2 分钟内看到总盘；至少 3 人能说出文化体验或视觉演绎；至少 2 人愿意保存或分享。

## 六、结果归档

将结果写入 `docs/user-test.md` 的“复盘结论”，只保留匿名编号和必要观察，不把姓名、生日或联系方式提交到仓库。每次修改后重新运行：

```powershell
npm run verify
```

在真实手机、真实用户和正式历法核验完成前，发布状态只能写“原型”或“小范围体验”，不能写“正式预测服务”。
