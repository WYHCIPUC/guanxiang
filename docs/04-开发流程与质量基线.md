# 开发流程与质量基线

> 文档编号：04 ｜ 状态：生效 ｜ 版本：v1.0（2026-10-06）
> 上位文档：[00-观象总纲.md](00-观象总纲.md)。本文是三部曲统一的日常开发规则：
> 谁的检查链为准、改动怎么留痕、伦理与无障碍的底线是什么。

---

## 一、命令约定

每个应用保留自己的完整检查链，根级提供总闸门：

| 应用 | 开发 | 完整验收 | 既有脚本 |
|---|---|---|---|
| 今时 | `npm run dev`（apps/jinshi） | `npm run check-release` | 单测 + 构建 + 发布文件 + 界面冒烟 |
| 步天 | `npm run dev`（apps/butian） | `npm run build && npm run test:smoke && npm run test:astro && npm run test:render && npm run test:interaction` | TS 检查 + 构建 + 冒烟 + 天文计算 + 渲染 + 交互 |
| 璇玑 | `npm start` / `npm run desktop:dev`（apps/xuanji） | `npm run verify` | 构建 + 桌面壳 + 方案 + 47 项烟测 + 发布 + HTTP |
| 共享包 | — | `npm test`（Vitest） | 自身单测 + 三应用全链 |
| **根** | — | `npm run verify:all` | 依序执行三应用完整验收 |

规则：

- **动哪个应用，跑哪个应用的完整链**；动了 `packages/` 则必须跑 `verify:all`；
- 检查链失败时禁止"跳过检查先提交"；检查脚本本身可以修，但要写进对应产品 CHANGELOG；
- 璇玑的 `verify` 六链结构是系列的黄金标准，另两应用新增检查时向它看齐（一条命令、全绿才算过）。

## 二、测试分层

| 层 | 工具 | 现状 | 整合后基线 |
|---|---|---|---|
| 单元测试 | Vitest | 今时有（时间/天文/历法）；步天无；璇玑为自研 Node 烟测 | 共享包必须有；今时现有用例成为 core 的基准用例 |
| 冒烟检查 | 各应用自研脚本 | 三应用均有 | 保留各自脚本，不改不并 |
| 交互检查 | jsdom / happy-dom | 步天交互链、今时界面冒烟 | 保留 |
| 真实浏览器 QA | 人工 + 记录文档 | 璇玑 browser-qa、今时待第一轮试用 | 沿用璇玑的 QA 记录格式（环境、步骤、结果、截图位） |
| 桌面 QA | 人工 + desktop-check | 璇玑独有 | 仅璇玑/未来观象台壳适用 |

**新增功能的测试门槛**：共享包新函数无单测不得合入；应用层新交互至少补一条冒烟断言。

## 三、改动留痕（三本账）

1. **产品 CHANGELOG**（各应用目录内）：任何用户可感知的改动；
2. **产品决策记录**（各应用 docs/decisions.md 或等价文档）：口径、范围、技术选型变化；
3. **整合决策记录**（`docs/decisions.md`，INT 系列）：跨产品事项——目录迁移、共享包 API 破坏性变更、联动协议（观象档案）修订、总纲修订。

跨应用的一次提交可以只写一本整合账 + 相关产品账，但不得两边都不写。

## 四、内容与考据流程

1. **来源登记先行**：新内容（文案、数据、图像、音频）先入各产品来源表（格式见
   [03-共享内核规划.md](03-共享内核规划.md) 第六节），再进代码；
2. **口径标注**：凡近似算法，UI 必须带"近似"角标；凡产品化演绎（如七十二候候应、
   28 日循环星官），必须带"演绎"标注——各产品现有约定不变，共享 core 后由
   `precision` 字段统一驱动；
3. **复核日期**：来源表每条目记录复核日期，超过 12 个月未复核的条目在发布检查中提示；
4. **古籍引用**：公版古籍可直接用，但需给出篇目；今人整理的数据需登记许可。

## 五、隐私与伦理基线（系列统一，取三项目最严口径）

- **无后端、无账号、无统计脚本、无外部 API**；新增任何网络请求需 INT 决策批准；
- 用户数据只存本地（localStorage / 桌面本地文件），提供导出、导入、单条删除与全部清除，
  删除操作不静默丢失（可撤销或二次确认）；
- 记录类数据（璇玑观象日志）永不进入跨产品档案（见 [01](01-产品整合与联动方案.md) 3.3）；
- 传统术数相关表述遵守璇玑既定边界：断语软化、不涉疾病寿夭婚丧具断言、不做付费改运暗示、
  MBTI 等现代工具标注"现代对照物"；
- 常驻免责文案统一为：`传统术数与历法内容为文化演绎，仅供文化体验与娱乐，不构成任何人生建议。`

## 六、无障碍与体验基线

- 键盘可达：核心操作（今时拖卷↔方向键、步天测星、璇玑转盘）均有键盘等价入口；
- `prefers-reduced-motion`：三产品均须响应（现璇玑/今时已实现，步天补齐）；
- 移动端：今时 375px 布局已验收，步天有基础适配，璇玑以桌面为主——各产品维持现有承诺；
- 对比度：正文文字对比度目标 WCAG AA（装饰性古风文字除外，但需提供等价可读信息）；
- 声音默认关闭，开启须用户主动。

## 七、发布检查清单（各产品通用项）

每次对外发布（网页更新或桌面打包）前，除各应用检查链外，逐项确认：

1. [ ] 三本账中该写的都写了（CHANGELOG / 产品决策 / INT 决策）；
2. [ ] 来源表无"待补"条目，复核日期有效；
3. [ ] 免责与口径标注在所有含术数/历法读数的页面可见；
4. [ ] 新增依赖无遥测/远程资源，许可证登记；
5. [ ] 构建产物相对路径可用（GitHub Pages 子目录）；
6. [ ] 对外宣传语不超出当前发布门槛（各产品"不能宣称"清单见 [05](05-发布与传播策略.md) 第三节）。
