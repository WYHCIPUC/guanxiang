## 二、@guanxiang/core —— 历法与天文纯函数内核

**定位**：全系列唯一的事实口径。三产品任何"时辰/节气/候/月相/日出日落"读数都从这里出。

### 2.1 模块与来源

| 模块 | API 草案（节选） | 从哪来 | 备注 |
|---|---|---|---|
| `calendar` | `getLunarDate(date)` `getGanzhi(date, {yearBoundary})` `getSolarTerm(date)` `getTermCountdown(date)` | 今时的 lunar-javascript 封装直接迁入 | 璇玑 D-008 口径（太阳黄经每 15°）为正式标准；`yearBoundary` 保留立春/春节开关位 |
| `hou`（七十二候） | `getHou(date)` `getPhenology(termIndex, dayOffset)` | 今时迁入 | 候应文案标注"产品化演绎"的规则一并迁入 |
| `solar` | `getSunTimes(date, lat, lon)` `getTwilightPhase(date, lat, lon)` `getTrueSolarTime(date, lon)` | 今时 src/systems 迁入 | 晨昏蒙影三级口径随迁 |
| `moon` | `getMoonPhase(date)` `getMoonPhaseName(date)` | 今时迁入 | 步天 V2 夜空复用 |
| `sky`（P2 预留） | `altAz(raDec, date, lat, lon)` | 步天接入真实星表时新增 | J2000→地平变换，步天专用为主 |
| `format` | `formatShichen(date)` `getGengDian(date)` … | 今时迁入 | 时辰刻更点文案统一 |

### 2.2 口径与精度规则

1. core 内所有函数必须带 `source` 与 `precision` 字段的文档注释（如"近似：固定日期表"“精确：香港天文台 2026 表"）；
2. **近似结果必须可被 UI 识别**：每个返回值带 `precision: 'exact' | 'approx'`，产品层据此渲染"近似"角标（三产品现有约定代码化）；
3. 璇玑现有近似算法**不迁入** core，等正式历法核验后由 core 的实现替换（璇玑 D-003 的"下一步"在此落地）；
4. core 的测试基准 = 今时现有 Vitest 用例（时辰边界、日出日落顺序、月相范围、节气解析）+ 璇玑补历法核验样本。

## 三、@guanxiang/palette —— 传统色系统

**定位**：系列视觉语言的代码化。三产品色板来自同一份 token。

### 3.1 内容

```
palette/
├── tokens.css        # CSS 自定义属性（天色 12 关键色、五行五色、金箔点缀、玄青/宣纸双底）
├── sky.ts            # 天色插值函数（今时的天色引擎抽通用化：t=时刻 → color）
├── wuxing.ts         # 五行→色加权混合（璇玑五行色引擎迁入）
└── README.md         # 色名考据（东方既白/暮山紫/绀青…逐色登记出处）
```

### 3.2 规则

- 色值以中国传统的**传统色名**为主键（如"暮山紫"），十六进制为值——色名即文档；
- 天色 12 关键色沿用今时创意文档的约定（黎明既白→天缥→暮山紫→玄青），步天入场氛围、璇玑盘面底色改为引用同一份 token；
- 五行五色沿用璇玑既定色值（木青 #2E6E55 …），五行色引擎输出即"一人一色"主色；
- 双底模式（玄青夜景 / 宣纸日景）作为系列级主题变量，各产品至少实现其一。

## 四、@guanxiang/cardkit —— 分享卡导出引擎

**定位**：此刻签、奏折、命纹卡三种卡面共用一套"排卡"基座。

### 4.1 能力清单

| 能力 | 说明 | 现有实现参考 |
|---|---|---|
| 竖排文本 | CSS writing-mode 的 SVG 等价实现（导出场景 DOM 方案不可靠） | 三产品各自 CSS |
| 印章 | 方章/圆章、朱砂色、篆意字体声明（字体文件与许可证由各产品自理） | 步天落款章、璇玑命纹章 |
| SVG → PNG | Canvas 栅格化导出，含 Blob URL 生命周期处理 | 璇玑 0.2.2 修复的下载问题沉淀为公共实现 |
| 系列水印 | "观象"系列标识 + 产品名小注（三卡同源规范） | 新增 |
| 系统分享 | `navigator.share` 可用时走系统分享，否则下载 | 今时已实现 |

### 4.2 边界

- cardkit 只做**导出基座**，不做卡面设计——三张卡各自的排版仍是各产品的产品层资产；
- 涉及用户输入（姓名等）上卡，沿用璇玑隐私约定：卡内不嵌入任何可回溯标识。

## 五、声音引擎（暂缓抽包）

三产品的声音诉求（今时环境声、步天更漏与磬、璇玑五音）共同约束已明确：
Web Audio 合成或 CC0、默认静音、用户主动开启、`prefers-reduced-motion` 联动。
P2 先在 palette 包里登记《系列声音规范》文档，等步天/璇玑实际做声音时再决定是否抽 `@guanxiang/audio`。

## 六、内容与考据的公共约定（不抽代码，抽格式）

三产品的来源登记统一为同一张表结构（字段：条目 / 来源 / 许可证 / 复核日期 / 口径备注），
今时 `src/content/sources.json` 为格式基准，步天 `SOURCES.md` 与璇玑 `content-sources.md`
在 P2 各加一份同结构 JSON，使"发布前来源审查"可脚本化。

---

## 七、依赖与构建

- core 依赖：`lunar-javascript`（MIT）——由 core 独占，应用不得直接 import；
- palette / cardkit 依赖：零运行时依赖（cardkit 的 canvas/SVG 全用标准 API）；
- 三包均输出 ESM + `.d.ts`，包内单测覆盖率以今时现有用例为底线；
- 版本独立演进，从 `0.1.0` 起；core 的版本号变更需同步登记 [decisions.md](decisions.md)。
