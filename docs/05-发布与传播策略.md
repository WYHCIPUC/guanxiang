## 一、发布矩阵

| 渠道 | 内容 | 节奏 | 责任应用 |
|---|---|---|---|
| GitHub Pages（各自子目录或独立仓库） | 今时、步天网页版 | 随版本 | 今时、步天 |
| PWA | 今时可安装到主屏 | 随版本 | 今时 |
| Windows 桌面安装包 | 璇玑（现为开发 Alpha） | 通过外部验收后启动打包 | 璇玑 |
| 观象台桌面壳 | 三合一入口（P4 远期） | 三产品均过外部验收后 | 整合层 |

**版本规则**：三产品各自独立版本号与 CHANGELOG；系列层面只在里程碑（如 P2 共享内核落地、P4 三殿壳）发布"系列动态"，写进本仓库根 README 的状态表。

**域名策略**（待负责人决策，当前不购买）：若未来统一域名，规划形如
`jinshi.example.com` / `butian.example.com` / 观象台门户 `example.com`；
在负责人确认前，一切发布走 GitHub Pages 免费渠道，不产生任何付费承诺。

## 二、三卡传播体系

三部曲的传播物是三张同源的卡，规范如下：

| 卡 | 产品 | 形制 | 共同点 |
|---|---|---|---|
| 此刻签 | 今时 | 横竖结合的签卡：时辰、候、花信、月相、诗文，配色取当下天色 | 系列水印"观象"、同款印章字体、朱砂印色、留一行系列小注 |
| 星图奏折 | 步天 | 竖排奏折：日期、地点、所测星、宿度/去极度、落款章 | 同上 |
| 命纹卡 | 璇玑 | 命纹印章 + 主色渐变 + 六字干支 + 本命星官 + 判语 | 同上 |

统一规范由 `@guanxiang/cardkit` 承载（见 [03-共享内核规划.md](03-共享内核规划.md) 第四节）：
水印位置、印章字体声明、卡片导出下载行为（Blob 生命周期处理）、系统分享优先策略。

**三卡各自的传播钩子**（沿用各创意文档，不另起炉灶）：

- 此刻签：任意时刻可取、天色配色千人千面——高频轻传播；
- 奏折：一次观测的成果，古风出片——深度传播；
- 命纹卡：一个人的长期身份标识（确定性生成）——身份传播。

## 三、当前宣传边界（各产品"不能宣称"清单，汇总自各产品文档）

| 产品 | 当前可宣称 | 不得宣称 |
|---|---|---|
| 今时 | 传统文化体验原型、时间可视化 | 精确历法工具、专业天文数据源 |
| 步天 | 星空文化体验原型、教学演示测量 | 专业天文测量精度、权威星官资料 |
| 璇玑 | Windows 桌面开发 Alpha / 小范围体验 | 正式预测服务、正式历法工具、心理或命理诊断 |

**解禁条件**（各自文档已定，此处只汇总）：历法核验、真实用户试用（3–5 人）、
外部设备验收完成后，由各产品决策记录逐项解除。宣传物料（含社交媒体文案）发布前
对照本表与 [04](04-开发流程与质量基线.md) 第七节清单检查。

## 四、节气营销日历（系列共用节奏）

二十四节气是三部曲天然的发布与内容节点（24 次/年免费流量）：

| 时机 | 动作 | 主推产品 |
|---|---|---|
| 交节日当天 | 自动生成"交节海报"（交节倒计时归零的此刻签变体） | 今时 |
| 节气夜 | "今晚这样看"天象专题（真实数据生成，如行星合月、流星雨） | 步天 |
| 节气当天 | "这个节气出生的你"命纹卡变体 | 璇玑 |

物料生成脚本化：海报模板复用 cardkit，数据来自 core（保证与站内读数一致）。
首个试点选一个较近的节气做全流程演练，再决定是否铺满 24 节气。

## 五、渠道与叙事

- **渠道**：小红书 / B站 / 即刻（三产品创意文档一致指向的渠道），以图卡与短视频为主；
- **系列叙事**（对外统一口径）：
  「观象」系列——把中国古人观天、计时、识己的完整世界观，装进浏览器与桌面。
  三个作品可以单独用，合起来是一部完整的"观象生活"；
- **预设标题**（沿用各创意文档积累）：
  - 《我把中国时间做成了一幅画》《你的申时三刻，长这样》（今时）
  - 《我给每颗中国星星起了名字，然后亲手测了它》《1054 年那颗客星，我替你回去看了》（步天）
  - 《输入名字和生日，换回一座属于你的宇宙》（璇玑）
- **交叉导流**：三张卡的系列小注互为入口；一篇内容只主打一个产品，结尾一句话带出系列。

## 六、发布日流程

1. 目标应用跑完整验收链（[04](04-开发流程与质量基线.md) 第一节）；
2. 过发布检查清单（[04](04-开发流程与质量基线.md) 第七节）；
3. 网页版：构建 → 部署 → 线上冒烟（今时 `smoke-ui`、步天手动核对入口）；
4. 桌面版：`desktop-check` + 目标机验收（璇玑 external-qa-runbook）；
5. 宣传物料对照第三节边界表复核后发布；
6. 在根 README 状态表登记本次发布。
