> 如何互相打通、打通的边界在哪里。

## 一、整合原则：联邦，不吞并

三个产品都已独立跑通各自的最小闭环，且各有一条已验证的主线：

- 今时：**天色与节气的时间觉知**（打开即得，日活型）；
- 步天：**中西双星空与亲手测星**（一次性深度体验，成果可分享）；
- 璇玑：**个人底色 + 每日观象记录**（持续使用型，桌面优先）。

整合的原则是：

1. **每间殿的独立主线不动。** 联动是给主线加钩子，不是改主线。
   璇玑的"今日观象 → 记录 → 复盘"仍是璇玑的主任务；
   步天的"看天 → 测天 → 记天 → 传天"四步仍是步天的行动线；
   今时的长卷仍是打开即定位"此刻"。
2. **联动必须可独立降级。** 没有另一款产品的数据时，本产品不得报错、不得空转，只隐藏联动入口。
3. **互通不经过网络。** 三产品间传递数据只靠本地导出/导入文件（观象档案，见第三节）。

## 二、三产品的独立定位（冻结口径）

| | 今时 | 步天 | 璇玑 |
|---|---|---|---|
| 用户拿到什么 | "此刻"的天色、时辰、候、月相 | 一晚的星空认知 + 一张亲手测的奏折 | 个人底色 + 一段自己写下的记录史 |
| 主线 | 长卷漫游 → 取签 | 观星 → 测星 → 奏折 | 观象 → 记录 → 复盘 |
| 日活理由 | 天色每天不同、节气倒计时 | 天象日历（流星雨、行星合月） | 每日记一件事、七日复盘 |
| 传播物 | 此刻签 | 星图奏折 | 命纹分享卡 |
| 发布形态 | 网页 / PWA | 网页 | Windows 桌面客户端（网页为开发预览） |

## 三、观象档案：三产品互通的数据格式

### 3.1 是什么

一份**纯本地 JSON 文件**，用户从任一产品导出、在另一产品导入，实现跨产品互认。
无账号、无云、无自动同步——用户自己搬自己的数据。

### 3.2 结构（v1 草案）

```jsonc
{
  "guanxiang": 1,                          // 格式版本
  "profile": {                             // 个人底色（璇玑生成）
    "name": "可选称呼",
    "birthDate": "1990-06-15",             // 公历
    "birthSolarTerm": "芒种",              // 生日节气（共享内核计算）
    "natalMansion": "参宿",                // 本命星官（二十八宿，口径待核验）
    "fiveElements": { "木": 2, "火": 1, "土": 2, "金": 2, "水": 1 },
    "primaryColor": "#2E6E55"              // 五行主色
  },
  "location": { "city": "上海", "lat": 31.23, "lon": 121.47 },   // 手动设置，不自动定位
  "exportedFrom": "jinshi|butian|xuanji",
  "exportedAt": "2026-10-06T21:00:00+08:00"
}
```

### 3.3 各产品的读与写

| 产品 | 读（导入后点亮什么） | 写（导出什么） |
|---|---|---|
| 步天 | 本命星官 → 星空里该宿连线描金高亮 + 一枚"本命"印章；生日节气 → 宿度环对应区间标记 | 地点设置、测星记录摘要 |
| 今时 | 生日节气 → 长卷上"你出生那天"的定位标记；主色 → 签卡描边取个人五行色 | 地点设置、签卡收藏 |
| 璇玑 | （档案的发起者，回读无损） | 个人底色全套 |

规则：

- 导入前必须**预览**将导入的字段（沿用璇玑日志导入的确认模式）；
- 任一产品不得写坏不认识的外来字段（前向兼容，未知字段原样保留）；
- 档案不含任何记录类隐私数据（璇玑观象日志**永不进入**观象档案，导出日志仍走璇玑自己的 JSON）。

## 四、四层联动设计（按实现优先级）

### L1 · 时刻互认（低成本，先做）

同一份"此刻"在三产品中一致：时辰、节气、候、月相、日出日落。
技术上由共享历法内核保证（见 [03-共享内核规划.md](03-共享内核规划.md)），
产品上在页面角落互放"此刻"一致口径的木牌视觉。

### L2 · 观象档案互认（中成本，P3）

上节的三产品读写字典。首个场景：**璇玑测出本命星官 → 步天夜空点亮**。
这是三部曲"天↔人"打通的顿悟时刻，优先做。

### L3 · 传播物互认（低成本，随各产品迭代）

三张分享卡统一：系列水印"观象"、统一印章字体与竖排规范、卡面互相留出
"系列另两作"的一行小字入口（如奏折落款旁一行小注"今时 · 璇玑 同源"）。
规范见 [05-发布与传播策略.md](05-发布与传播策略.md)。

### L4 · 观象台壳（高成本，P4 远期）

璇玑的 Electron 桌面壳扩展为"观象台"：一座台、三间殿的桌面入口
（窗口内导航：今时 / 步天 / 璇玑）。**前置条件**：三产品均完成各自的外部验收。
在此之前，不做任何壳层面的合并。

## 五、联动场景清单（验收用）

| 编号 | 场景 | 完成判据 |
|---|---|---|
| S-01 | 璇玑导出观象档案 → 步天导入 | 步天星空中本命宿描金高亮，悬停显示"本命星官 · 出《璇玑》" |
| S-02 | 璇玑导出 → 今时导入 | 今时长卷出现"生于芒种"的节气标记，签卡描边用个人五行色 |
| S-03 | 无档案时打开步天/今时 | 不出现任何报错与空状态提示，联动入口不渲染 |
| S-04 | 三产品同一分钟内对照 | 时辰、节气、候、月相读数完全一致（同一内核保证） |
| S-05 | 三张分享卡并排 | 同一水印、同一印章字体、色系协调，一眼可辨同源 |

## 六、明确不做的事

- 不做账号系统与跨设备云同步；
- 不做三产品数据自动互写（互通一律显式导出/导入 + 预览确认）；
- 不在对方产品内推送另一产品的运营消息（联动入口只陈述，不打扰）；
- 不为联动牺牲任一产品的离线可用性（观象档案导入导出全部本地完成）；
- 不把"本命星官"等未核验口径包装成精确结论——联动 UI 沿用各产品既有的口径标注。
