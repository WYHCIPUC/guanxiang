## 一、现状盘点

| | apps/jinshi/ | apps/butian/ | apps/xuanji/ |
|---|---|---|---|
| 构建 | Vite 6 | Vite 8 | 无构建（源码即静态文件） |

| 运行时依赖 | lunar-javascript | react / react-dom / lucide-react | 无 |
| 本地服务器 | Vite dev | Vite dev | 自研 Node 静态服务器 `scripts/server.mjs` |

三个仓库边界清晰、无相互依赖，这是整合最大的本钱；差异最大的是璇玑（无构建、无 TS、桌面壳）。

## 二、整合策略（三条铁律）

1. **不推倒重来。** 三个产品都已通过各自的原型验证，整合只做"搬运与抽取"，
   不重写任何已验证的业务代码。
2. **每个应用永远可独立构建、独立运行、独立发布。** monorepo 是共享便利，
   不是单点耦合：任何时刻删掉 `packages/`，三个应用应仍能各自跑起来（允许功能降级）。
3. **共享包零框架依赖。** `packages/` 里只允许纯 TypeScript / 浏览器标准 API，
   不允许 import react / electron / vite 插件。这保证今时（无框架）、步天（React）、
   璇玑桌面壳三类宿主都能用同一份内核。

## 五、技术栈统一策略

### 5.1 语言与构建

- **TypeScript 为共同语言**：共享包一律 TS；璇玑存量 JS 不强制改写（允许渐进，
  新模块用 TS 写在 `apps/xuanji/src/core-ts/` 由 tsc 直接编译或 P2 引入 Vite，见 5.3）。
- **Vite 版本各自保留**：不为了统一而升级/降级任何应用，等各自自然升级时靠拢同一大版本。
- **相对路径部署**是三产品共同约定（GitHub Pages 子目录），共享包打进各自 bundle，不做运行时 CDN 引用。

### 5.2 依赖治理

- 根 `package.json` 只放 workspaces 声明与根级脚本，不放业务依赖；
- 三应用重合的依赖（typescript、vite、happy-dom/jsdom）在 P2 用 workspaces
  提升到根统一版本；lunar-javascript 收进 `packages/core` 的依赖；
- **禁止引入**任何含统计、遥测、远程字体的运行时依赖（三产品现有约定合并延续）。

### 5.3 璇玑的两种演进路线（P2 决策点）

| 路线 | 内容 | 何时选 |
|---|---|---|
| A · 保持零构建 | 继续原生 JS + Node 静态服务器，共享包用 tsc 预编译产物（ESM + .d.ts）引入 | 桌面壳稳定性优先时 |
| B · 引入 Vite | 与另两应用对齐，dev 体验与 tree-shaking 统一 | 需要共享包源码级联调、或网页版重新提级时 |

默认 A（改动最小），触发条件见 [06-整合路线图.md](06-整合路线图.md) P2 门槛。

### 5.4 桌面壳

璇玑 Electron 壳（`xuanji://bundle/` 固定协议、上下文隔离、无 Node 集成）是
系列唯一的桌面宿主。P4 若做"观象台三殿壳"，沿用其全部安全边界
（见 `apps/xuanji/docs/desktop-client-plan.md`），只增加应用切换导航，不放宽任何权限。

### 5.5 测试工具链

- 单测统一 Vitest（今时已用；步天 P2 补单测；共享包从第一行代码起必须有单测）；
- 各应用保留自研烟测/交互检查脚本（它们是各产品验收链的一部分，不推倒）；
- 根级新增 `npm run verify:all`：依次执行三应用完整检查链，作为整合后的总闸门。

## 六、代码所有权与协作规则

- `apps/*` 内的代码由各产品文档与决策记录治理，跨应用的改动须同时更新对应产品 CHANGELOG；
- `packages/*` 的改动需过两道门槛：自身单测全绿 + 三个应用 `verify:all` 全绿；
- 共享包 API 破坏性变更必须升主版本号并同步改三应用调用方，不允许"先改后补"。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 中文目录名在工具链（npm/electron/CI）中的编码隐患 | P1 迁移时统一改英文目录名 `apps/jinshi|butian|xuanji`，产品中文名只留在 UI 与文档 |
| 三套 node_modules 复制后体积膨胀、幽灵依赖 | 迁移后根级 `npm install` 重建，workspaces 去重；验证三应用均从根 node_modules 解析 |
| 步天"静态 index.html + React app.html"双实现漂移 | 维持现状（README 已声明两者关系），P2 起以 React 版为唯一开发主线，静态版只作发布快照 |
| 共享包被某应用的特殊需求绑架（如璇玑桌面离线 vs 网页懒加载） | 共享包只做纯函数与声明式资产，宿主相关的加载策略留在各应用 |
| Electron 大依赖拖慢整体安装 | electron 保留在 `apps/xuanji/devDependencies`，不进根依赖 |
