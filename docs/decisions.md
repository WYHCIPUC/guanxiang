# 整合层决策记录（INT 系列）

> 本文件只记录**跨产品**的整合决策。各产品内部决策见各自目录
> （`docs/butian/decisions.md`、`璇玑/docs/decisions.md` 等）。
> 决策变更须新增条目，不修改历史条目正文（勘误除外）。

---

## INT-001：采用"联邦式"整合，不合并产品

- 日期：2026-10-06
- 决策：三项目保持独立可运行、独立发布、独立版本；整合层只做文档统一、
  仓库归一、共享内核与可选联动。
- 原因：三个产品均已独立验证各自闭环；合并成单产品会破坏已验证的主线，
  且三者形态差异大（网页/PWA/桌面）。
- 代价：三份依赖与配置短期并存；共享只能渐进抽取。

## INT-002：系列命名为「观象 · 天时人三部曲」

- 日期：2026-10-06
- 决策：系列总名"观象"，三部分别为《今时·中国时间》（时）、《步天》（天）、
  《璇玑·数字观象台》（人）；题眼取《周易·贲·彖》"观乎天文，以察时变；观乎人文，以化成天下"。
- 原因：璇玑副标题已是"数字观象台"，三作主题天然构成"天—时—人"；
  "观象"一词同时覆盖观星、授时、知人三个古代职能，出处正统。
- 备注：对外品牌展示为"观象系列"；仓库根目录名暂不改（见 INT-007）。

## INT-003：P0 只整合文档，不动代码

- 日期：2026-10-06
- 决策：本次整合仅建立总纲层文档并把步天单项目文档归位 `docs/butian/`；
  三产品代码零改动（`scripts/smoke-check.mjs` 的两处路径引用除外）。
- 原因：三产品检查链均已绿色，先用文档对齐认知，再动结构；降低一次变更的风险面。
- 验证：步天 `test:smoke` 迁移后通过。

## INT-004：共享包零框架依赖

- 日期：2026-10-06
- 决策：`packages/*` 只允许纯 TypeScript 与浏览器标准 API，禁止依赖
  react / electron / vite 插件。
- 原因：今时（无框架）、步天（React）、璇玑（原生 JS + Electron）三类宿主
  必须能共用同一份内核。
- 代价：共享包实现须克制，宿主相关的策略留在应用层。

## INT-005：跨产品互通只用本地"观象档案"，不建后端

- 日期：2026-10-06
- 决策：产品间数据互通采用显式导出/导入的本地 JSON（观象档案 v1，
  见 01 文档第三节）；不建账号、云同步与任何网络通道。
- 原因：延续三项目"无后端、本地优先"的既定共识；观象日志等隐私数据不跨产品流动。
- 代价：跨产品体验需用户手动搬一次文件。

## INT-006：尊重并锁定各产品关键既有决策

- 日期：2026-10-06
- 决策：以下既有决策在整合后继续有效，整合不得推翻：
  - 璇玑：Windows 桌面客户端为主要形态；主线为"今日观象—日志—七日复盘"价值闭环；
  - 三产品：无账号/无后端/无追踪；历法与术数口径为"原型/文化演绎"，
    核验完成前不得宣称专业工具；
  - 今时：第一轮试用后再决定内容量扩张。
- 原因：这些决策各有真实的验证依据（原型复测、外部资料复核），整合无新证据不应翻案。

## INT-007：仓库目录名与产品目录名暂不改

- 日期：2026-10-06
- 决策：当前目录结构（根为步天、子目录 `今时中国/`、`璇玑/`）维持到 P1；
  P1 迁移时统一改为 `apps/jinshi | butian | xuanji`，仓库根是否更名由负责人届时决定。
- 原因：中文目录名有工具链编码隐患，但立即改名会同时打断三份在用的启动脚本与
  使用习惯；合并进 P1 一次做。
- 代价：P1 前新文档需容忍中文路径。

## INT-008：璇玑 verify 检查链为系列黄金标准

- 日期：2026-10-06
- 决策：以璇玑 `npm run verify` 的"一条命令串联全链"模式为系列验收范式；
  根级 `verify:all` 按此模式串联三应用。
- 原因：璇玑的检查链经过真实发布迭代沉淀（47 项烟测、HTTP 检查、外部门槛文档），
  是三项目中工程化最成熟者。

## INT-009：P1 仓库归一执行口径

- 日期：2026-10-06
- 决策：P1 迁移当日执行完毕，除 02 文档映射表所列动作外，明确以下执行口径：
  1. **`.github/workflows` 保留在仓库根**（修正 02 文档映射表把 `.github/` 随步天迁走的表述——
     GitHub 只识别仓库根的 workflow）。workflow 已改为在 `apps/butian` 内安装、构建、检查并
     上传 `apps/butian/dist`；
  2. **三应用包名统一 `@guanxiang/*`**（butian / jinshi / xuanji），各自 lockfile 同步改名；
  3. **根级 `npm install` 复用各应用既有 node_modules**，不强制全量提升去重；依赖版本统一
     留待 P2 处理（见 02 文档 5.2）；
  4. **步天验收链扩为五步**：build + test:smoke + test:astro + test:render + test:interaction
     （当日新增天文计算检查与 React 渲染检查，向璇玑"一条命令全链"黄金标准看齐）。
- 前置说明：璇玑桌面外部验收尚未完成；因 06 文档明确该项"无硬性时间依赖"，经负责人授权按
  推荐口径推进迁移。外部验收仍需在迁移后的目录上重新执行一轮目标机检查。
- 验证：根 `npm run verify:all` 三应用七链全绿；`启动璇玑.bat/ps1` 使用 `%~dp0`/`$PSScriptRoot`
  自相对路径，迁移后无需修改；根 README 与总纲 00/02/04/06 文档路径已同步。
